# ## 6.3 Threat model, authorization, and least privilege for financial MCP deployments

The relevant attacker is not only an external network intruder. A threat can originate from a malicious document, a compromised server, excessive permissions, stale configuration, unsafe retry logic, an insider, a vendor update, or an ordinary implementation error. Indirect prompt injection is especially important because untrusted text retrieved as evidence can attempt to alter the model's tool behavior [Greshake et al., 2023].

A financial MCP deployment therefore needs a threat model that links each failure mode to a concrete control owner. The control should not depend on the model following an instruction. It should be enforced by the host, policy engine, server registry, identity system, validation layer, or execution adapter.
