typed document, claim, tool-call, version, and audit objects; a deterministic retrieval smoke test; timestamp-leakage checks; claim-support scoring; calibration metrics; and guarded tool execution. These are not substitutes for enterprise systems; they are executable specifications of the design principles used in the manuscript. The directory companion/experiments/rag_sec_filings contains a credential-free smoke benchmark with fictional filings, questions, a runnable script, a results table, and an audit log.

The directory companion/experiments/pit contains the Chapter 13 generator, machine-readable book results, the seed-11 run, and the declared 60-seed drift decomposition. These benchmarks test reproducibility and governance; they are not evidence of live market forecasting performance.

The most important mathematical invariant enforced by the reference implementation is

$a_j \le t$ for every evidence item $d_j$ used at decision time $t$.

If this inequality fails for any retrieved item, the pipeline should reject the run. This single inequality is the operational form of the no-lookahead propositions in Chapters 3, 4, and 14.

# Listing 15.6: Minimal use of the companion package

```
from datetime import datetime, timezone
from finllm.contracts import Claim, Document, EvidenceBundle
from finllm.rag import faithfulness_score, retrieve_by_bm25_like
from finllm.temporal import assert_documents_available

now = datetime(2026, 7, 1, tzinfo=timezone.utc)
corpus = (
    Document(
        document_id="filing-001",
        text="Revenue increased by 8 percent in fiscal 2025.",
        source="10-K",
        timestamp=datetime(2026, 2, 15, tzinfo=timezone.utc),
    ),
)
assert_documents_available(corpus, decision_time=now)
evidence = retrieve_by_bm25_like("How did revenue change?", corpus, k=3)
claim = Claim(text="Revenue increased by 8 percent.")
print(faithfulness_score([EvidenceBundle(claim, evidence)]))
```

The example is intentionally small and uses the interface implemented by the tagged companion release. It captures the essential production habit: the system stores evidence identifiers, checks availability times, retrieves from a valid corpus, and evaluates whether claims are cited. A more sophisticated implementation may use dense embeddings, hybrid search, cross-encoder re-ranking, claim-level natural-language inference, and immutable audit storage; the invariant remains the same.
