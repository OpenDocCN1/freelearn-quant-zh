The principal disadvantages are capital commitment, power and cooling constraints, hardware refresh risk, spare-capacity requirements, and the need to operate the full platform. Capacity planning must include maintenance windows and failure domains: an eight-GPU server that meets average demand may not satisfy the service objective after a GPU, node, or network path fails.

# Hybrid and edge architecture strategies

Hybrid architectures are often appropriate because different stages of a financial workflow have different constraints [Daniëlsson et al., 2022]. Public or private cloud can support experimentation, large but temporary training runs, and non-sensitive batch jobs. Customer-controlled infrastructure can host sensitive inference, proprietary retrieval stores, and audit records. Edge nodes can execute narrowly scoped filtering or classification near users or data sources, while a centralized service handles complex generation and policy enforcement.

The practical design rule is to keep the latency-critical path as short and deterministic as possible. A small classifier or rules engine may execute at the edge, but a generative model whose response is not required for immediate action should run asynchronously. Sensitive data should not cross a wide-area network merely to save local compute. Conversely, duplicating the complete LLM stack at every edge site increases patching, monitoring, model-consistency, and incident-response burdens. A sound hybrid design therefore specifies which data can leave each zone, which decisions can be made locally, how models are updated, how confidence-based escalation works, and what fallback behavior applies when the cloud or central cluster is unavailable.

# 10.2 Data architecture and pipeline design

Financial LLM systems depend on pipelines that can ingest, clean, enrich, retrieve, and update information reliably. Production pipeline architecture must support both real-time streams, such as market events and news, and slower-moving sources, such as filings, research reports, policies, and internal documents. Data lineage should connect each generated output to source records, parsing versions, feature transformations, embedding versions, and retrieval results.

# 10.2.1 Real-time data ingestion systems

Market-data volumes vary substantially by asset class, venue coverage, normalization policy, and whether quote-book updates are retained. Rather than presenting one institution-specific figure as a universal benchmark, capacity planning should state an explicit workload profile. For example, an illustrative design point of 10 billion events per day corresponds to an average of approximately 116,000 events per second. A five-million-event-per-second burst would therefore represent a burst-to-average ratio of roughly 43. Such a profile is useful for stress testing, but it should not be described as typical without evidence from the institution’s subscribed feeds and retention policy.
