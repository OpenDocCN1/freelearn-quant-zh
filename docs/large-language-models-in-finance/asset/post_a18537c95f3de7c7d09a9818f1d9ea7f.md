
**Definition 13.5.1** (Prefix-causal artifact). Let $H$ be a complete history of source records, each carrying an availability stamp, and let $B_t(H, \xi_t)$ be a build map that is formally allowed to receive the complete history. The build map is *prefix causal* at cutoff $q_t$ when there exists a measurable map $\widetilde{B}_t$ with $B_t(H, \xi_t) = \widetilde{B}_t(H_{\le q_t}, \xi_t)$ for every complete history $H$: two histories that agree through $q_t$ produce the same artifact under the same ex-ante random state. An artifact is point-in-time admissible for decision date $d$ only if its build factors through the historical prefix in this sense and $\rho(\mathcal{A}_t) \le q_d$.

Two conditions make this operative rather than decorative. The random state $\xi_t$ must be drawn *ex ante* and fixed — shared across the two histories in the definition — since a build that reseeds on the data it sees is not a function of the prefix alone. And every third-party component (a hosted model behind an API, a managed embedding endpoint, a vendor retrieval index) must be pinned to an immutable version identifier. A mutable API alias silently violates prefix causality without changing a single line of the caller's code, and it is the one violation that survives every code review, because the code did not change.

The clock matters as much as the artifact. Each trading day $d$ on a venue-specific calendar has a decision cutoff $q_d$ before intended execution, such as the market-on-close deadline. An article with first vendor availability $u_j$ and end-to-end latency $\lambda_j$ (ingestion, parsing, inference, routing) has effective trading date

$d(j) = \min\{d \in \mathcal{T} : u_j + \lambda_j \le q_d\},$ (13.4)

where $\mathcal{T}$ is the venue's trading calendar — an explicit, versioned list of sessions with their cutoffs, including early closes and holidays, and not a generic business-day rule. Late news rolls forward to the next admissible session in $\mathcal{T}$ and is never assigned backward. If no session in the evaluation window satisfies the constraint (the article arrives after the last cutoff), the score is *undefined* rather than deferred to a session outside the sample; silently deferring is how coverage leaks back into a supposedly clean run. The deployed vintage is the latest admissible artifact by that cutoff, $v(j) = \max\{t : \rho(\mathcal{A}_t) \le q_{d(j)}\}$, with no backfilling: if no admissible artifact exists, the score is missing rather than imputed. Forward labels follow the same discipline. An $h$-session label for article $j$ completes at $k_j = \sigma^h(d(j))$, where $\sigma$ is the successor map on the trading calendar $\mathcal{T}$ — *not* integer addition on dates, which would silently cross weekends and holidays and shorten the true realization lag. A model built at vintage $t$ may train only on labels with $k_j < t$; conditioning instead on $d(j) < t$ silently admits the $h$ most recent cohorts before their outcomes are known, a label-realization leak that survives many code reviews.

## 13.5.2 Six channels of look-ahead

Table 13.4 organizes the failure modes of (13.1) as an artifact-data-execution system. The first four channels can be closed algorithmically given auditable source data; the last two require data contracts and research governance in addition to code. The channels are diagnostic rather than mutually exclusive — one contaminated component can instantiate several at once — and they refine, at the object level, the layered taxonomy introduced earlier in this chapter.

| Channel | Typical violation | Point-in-time control |
|---|---|---|
| 1 | Artifact vintage | Dictionary, tokenizer, base model, task head, prompt, calibrator, or retrieval index uses post-date information. | Version and audit the complete artifact; require prefix-causal provenance and deployment before use. |
| 2 | Label realization | A model dated _t_ trains on an h-day outcome whose terminal price is unknown at _t_. | Train only on labels whose known date is strictly before the build vintage. |
| 3 | Transformation vintage | Full-sample standardization, winsorization, ranks, IDF, calibration, or feature selection. | Fit every transform on a lagged prefix and stamp it as part of the artifact. |
| 4 | Timestamp actionability | Revision or vendor stamps replace first availability; latency and order cutoffs are ignored. | First availability, venue cutoffs, latency, early-close calendars, explicit execution timing. |
| 5 | Corpus survivorship | Current constituents, tickers, revised text, or backfilled archives projected into the past. | Point-in-time entity maps, universes, corporate actions, delistings, as-first-available text. |
| 6 | Evaluation selection | Hyperparameters, prompts, horizons, or periods selected on the final statistic. | Pre-specification, nested walk-forward selection, search disclosure, untouched holdout. |

Table 13.4: Six channels of look-ahead in text signals.

Channels 1–4 are closable in code conditional on auditable inputs; channels 5–6 also require contracts and governance.

Channel 1 is broader than “model weights”: a tokenizer can reveal future vocabulary, a prompt can be selected after inspecting the test period, and a mutable API alias can silently change the model used to replay a backtest. Channel 3 is likewise broader than a _z_-score; every estimated transform has a vintage of its own.

## 13.5.3 What a clean pipeline actually guarantees

Five signal-level assumptions make the guarantee precise, with a sixth, ex-ante research design, governing evaluation selection: **(D1)** text and event metadata are as-first-available, with revisions versioned rather than substituted; **(D2)** prices, entity resolution, universes, and delistings are point-in-time; **(D3)** every data-dependent component of (13.3) has a documented prefix-causal build map, with supervised parts trained only on realized labels; **(D4)** build, release, deployment, inference, and routing complete before the relevant cutoff, with conservative latency in (13.4); and **(D5)** code, dependencies, model or API version, prompt, retrieval snapshot, and random state are pinned, so replay never queries mutable future state. Let \(\mathcal{H}_d^\text{PIT}\) be the information generated by all records available by _q<sub>d</sub>_, the pre-specified maps, and only those artifacts satisfying D3–D5, and call two complete histories _d_-equivalent when they agree on these admissible inputs through _q<sub>d</sub>_.

**Proposition 13.5.1** (Point-in-time artifact correctness). Under D1–D5, the article scores with d(j) = d, the aggregate S_{a,d}, the normalized signal z_{a,d}, and the decision π_d are H_d^{PIT}-measurable, and the pipeline is temporally non-interfering: π_d(H) = π_d(H') for any two d-equivalent histories. Changing any future-only text, label, price, model component, retrieval document, or configuration cannot change the decision formed for date d.

Proof. By (13.4) and D1, every article assigned to d is available before the cutoff with fixed historical content. By D3 each component of A_{v(j)} factors through the historical prefix; by D4 the assembled artifact is operationally available before q_d; by D5 its application is replayable without mutable future state. Hence each score takes the same value in any two d-equivalent histories. Aggregation is deterministic in those scores and D2 entity tags, the lagged transform uses only strictly prior observations, and the pre-specified portfolio map receives only z_{.,d} and the point-in-time universe. Both properties are preserved under composition.

The proposition's substance lies in its premise, not its algebra. An ex-post model treated as a fixed constant is formally measurable with respect to every information set; measurability alone can therefore never convict a contaminated scorer. What carries the chronology is D3: the artifact must be generated by an auditable prefix-causal build. Freezing a future-trained object does not satisfy that premise. This is the precise sense in which the filtration condition stated earlier in this chapter must be read: it binds the provenance of the measurement apparatus, not merely the feature matrix it consumes.

## 13.5.4 Magnitudes: a controlled decomposition

How large are these channels? To answer that without confounding, I built a synthetic corpus in which the truth is known: 100 assets, 1,400 abstract market sessions, roughly 28,000 articles with simulated publication times, a 15:30 decision cutoff with 15-minute latency, and a return process in which sentiment impact begins the day after publication and decays over three days. A transparent shrunken word-tilt lexicon — every fitted weight inspectable at every vintage — is deployed walk-forward under a clean point-in-time protocol and under five named violations: a full-sample supervised oracle (A1) fitted once on all labeled articles including evaluation-period outcomes; a matched-size future oracle (A2) that keeps A1's temporal reach but exactly matches the clean protocol's training count; label admission before realization (B); full-sample normalization (C); and timestamp fiction (D), which ignores latency and cutoffs and rebuilds the entire chronology on publication-day stamps. Comparisons are paired on strictly common asset-days, with Newey–West statistics [Newey and West, 1987] and block-bootstrap intervals, and separately on each protocol's native support, where coverage itself becomes part of the treatment.

Every number here is produced by pit_experiment.py, shipped with the companion materials: python3 pit_experiment.py --seed 11. The script carries a self-test asserting the temporal non-interference property of Proposition 13.5.1: perturbing future-only labels must leave the clean artifact unchanged, and the test fails loudly if it does not. The world is simulated, so the truth is known by construction — which is the point, because the size of a look-ahead bias cannot be measured on real data, where the counterfactual is unavailable.
