LLM agents and multi-agent systems represent a powerful new paradigm for building intelligent systems in finance. By combining the generalization capabilities of large language models with structured tools, data sources, and human oversight, financial institutions can automate complex workflows while maintaining control and accountability.

# 5.7 Formal safety contract for agent workflows

The safest way to build financial agents is to treat the LLM as a proposal generator, not as an authority. The authority belongs to typed tools, policy gates, audit logs, and human reviewers. This distinction is the difference between an impressive demo and a deployable workflow.

**Definition 5.7.1** (Governed tool call). A governed tool call is a tuple

$C = (u,r,T,p,s,v),$

where $u$ is the user identity, $r$ is the user's role, $T$ is the requested tool, $p$ is the proposed parameter object, $s$ is the workflow state, and $v$ is the relevant version vector containing model, prompt, tool-schema, corpus, and policy versions. A policy gate is a function

$\text{Gate}(C) \in \{\text{allow}, \text{reject}, \text{escalate}\}.$

A workflow is fail-closed if every missing permission, invalid schema, stale artifact, or failed verification maps to reject or escalate, never to allow.

**Proposition 5.7.1** (No unauthorized execution under a fail-closed gate). Assume every external action requested by an agent is represented as a governed tool call $C$, every tool adapter executes only after receiving allow from Gate, and the gate is sound in the sense that unauthorized calls never map to allow. Then no unauthorized external action is executed, regardless of the free-form text generated by the LLM.

Proof. Every external action must pass through a tool adapter. By assumption, the adapter has only one execution path: it runs the tool after the gate returns allow. If a call is unauthorized, gate soundness implies that the returned decision is either reject or escalate. In both cases the adapter does not execute the external action. Since the LLM has no direct access path around the adapter, generated text alone cannot execute an unauthorized action.

The proposition is intentionally modest. It does not say the agent will always make good recommendations, nor that authorized actions are economically wise. It says something narrower and operationally essential: if all action authority is concentrated in a sound fail-closed gate, a language model cannot bypass permissions by persuasion, prompt injection, or malformed text.
