# ## 4.4.2 Contrastive learning for embeddings

Modern embedding models employ contrastive learning objectives [Gao et al., 2021, Chen et al., 2020]. Given a batch of training examples $(q_i, d_i^+, \{d_i^{-,j}\}_{j=1}^m)$ where $q_i$ is a query, $d_i^+$ is a relevant document, and $\{d_i^{-,j}\}$ are negative (irrelevant) documents:

The InfoNCE (Noise Contrastive Estimation) loss is defined as:

```
$$\mathcal{L} = - \log \frac{\exp(\text{sim}(f(q_i), f(d_i^+))/\tau)}{\exp(\text{sim}(f(q_i), f(d_i^+))/\tau) + \sum_{j=1}^m \exp(\text{sim}(f(q_i), f(d_i^{-,j}))/\tau)}$$
```

where $\tau$ is a temperature parameter controlling the sharpness of the distribution.

The temperature parameter $\tau$ plays a crucial role: smaller $\tau$ creates sharper distributions, while larger $\tau$ smooths the distribution. Typical values range from $\tau = 0.05$ to $\tau = 0.1$.

# ## 4.4.3 Financial embedding models

The choice of embedding model directly affects retrieval accuracy, particularly when working with domain-specific finance terminology and structured disclosures. We distinguish here, therefore, between general-purpose and domain-specific models.

In practice, practitioners typically begin with general-purpose models such as:

+   * OpenAI text-embedding-3-large (3072-dim)
+   * Cohere embed-english-v3.0 (1024-dim)
+   * sentence-transformers/all-mpnet-base-v2 (768-dim)

However, as retrieval requirements become more specialized, especially when dealing with financial filings, research reports, or internal documents, domain-specific models such as:

+   * retrieval-trained sentence encoders (for example the E5, GTE, and BGE families, or sentence-transformers models), further fine-tuned on financial corpora with contrastive pairs drawn from the target document type
+   * custom encoders fine-tuned on proprietary filings, memos, or transcripts, evaluated on retrieval metrics rather than on classification accuracy

Two clarifications are worth making because the field is careless about them. **A classifier is not an embedding model.** ProsusAI/finbert is a financial *sentiment classifier*; its hidden states can be pooled into vectors, but it was never trained with a retrieval objective and it will underperform a purpose-trained encoder on nearest-neighbour search. **BloombergGPT is not an embedding service.** It is a proprietary generative model [Wu et al., 2023b]; there is no publicly released checkpoint and no deployable embedding endpoint, so it cannot appear in a retrieval stack a reader can actually build. Naming a model that cannot be obtained is not a design recommendation. In practice, many systems begin with general-purpose retrieval encoders and progressively incorporate domain-specific fine-tuning as requirements become more specialized.
