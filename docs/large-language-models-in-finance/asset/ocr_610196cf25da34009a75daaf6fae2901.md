'preferred': responses[i],
'rejected': responses[j],
'confidence': self.compute_confidence(
    rankings[i], rankings[j])
})

# Quality control
filtered_data = self.quality_control.filter_preferences(
    preference_data)

return filtered_data

def compute_confidence(self, rank1, rank2):
"""
Compute confidence in preference based on rank difference.
"""
return 1.0 - np.exp(-abs(rank1 - rank2))

# 9.3 Modern RL and preference-optimization algorithms for LLMs

Policy gradients provide the foundation for RL-based alignment, but practical LLM training requires methods that make updates more stable and easier to control. PPO, GRPO, and DPO address this problem in different ways: PPO constrains online policy updates, GRPO estimates relative advantages from groups of completions, and DPO optimizes directly from offline preference pairs. Table 9.1 summarizes the main distinctions.

| Method | Training signal | Additional learned components | Operational trade-off |
| :--- | :--- | :--- | :--- |
| PPO | Scalar rewards on newly sampled responses | Usually a reward model, a reference policy, and a learned value-function critic | Stable clipped updates, but a comparatively complex and memory-intensive online training loop |
| GRPO | Rewards normalized within a group of responses to the same prompt | Reward source and reference policy, but no separate value-function critic | Lower critic-related memory usage; performance depends on group sampling and the quality and dispersion of rewards |
| DPO | Preferred/rejected response pairs | Fixed reference policy; no explicit reward model or critic during DPO optimization | Simple offline objective, but learning is limited by the coverage and quality of the preference-pair dataset |
