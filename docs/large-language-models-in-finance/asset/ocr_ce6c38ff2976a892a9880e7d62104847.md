where the retrieved set is selected by

\(\{d_1, \dots, d_k\} = \arg\max_{\{d_1, \dots, d_k\} \subset \mathcal{D}} \sum_{i=1}^k \log p(d_i \mid q).\)

We now examine one of the most critical components of RAG systems: embedding models.

# ## 4.4 Embedding models

Embedding models form the foundation of semantic retrieval in RAG systems. In the pipeline introduced earlier, they are responsible for representing both documents (during indexing) and queries (during retrieval) in a shared vector space, enabling the system to identify relevant context better.

We begin with the theoretical foundations of dense embeddings, then examine how modern models are trained and adapted for financial applications.

# ### 4.4.1 Dense embeddings

An embedding model is a function \(f : \mathcal{X} \to \mathbb{R}^d\) that maps text \(x \in \mathcal{X}\) to a dense vector representation in \(d\)-dimensional space [Reimers and Gurevych, 2019]. In this space, semantically similar inputs are positioned close together, allowing similarity to be measured using simple distance metrics.

In the real world, not all embeddings are equally useful for retrieval tasks. Effective embeddings must satisfy several properties:

+   1. **Semantic similarity**: The similarity \(\text{sim}(f(x_1), f(x_2))\) should correlate with the semantic similarity of \(x_1\) and \(x_2\).
+   
+   2. **Task relevance**: Embeddings should capture features relevant to downstream retrieval tasks.
+   
+   3. **Computational efficiency**: Fast to compute and amenable to efficient similarity search.

Common similarity metrics for dense embeddings include:

+   Cosine Similarity: \(\text{sim}_{\cos}(u, v) = \frac{u \cdot v}{\|u\|_2 \|v\|_2}\)
+   
+   Euclidean Distance: \(d_2(u, v) = \|u - v\|_2\)
+   
+   Dot Product: \(\text{sim}_{\text{dot}}(u, v) = u \cdot v\)

In practice, the quality of retrieval in RAG systems depends heavily on how well embeddings capture relevance, which is typically achieved through contrastive learning objectives.
