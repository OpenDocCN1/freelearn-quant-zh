# 4.7.4 Parent document retrieval

Small chunks are easier to rank precisely, but often lack the context the language model needs to answer well. Parent document retrieval resolves this tension by indexing fine-grained chunks for matching, then returning the larger document or section to which each retrieved chunk belongs.

Let \( C = \{c_1, \dots, c_m\} \) be chunks derived from parent documents \( D = \{d_1, \dots, d_n\} \) with mapping \( \pi : C \rightarrow D \). Parent document retrieval:

+   1. Retrieves relevant chunks: \(\{c_{i_1}, \dots, c_{i_k}\} = \text{TopK}(q, C)\)
+   2. Returns parent documents: \(\{\pi(c_{i_1}), \dots, \pi(c_{i_k})\}\)

This strategy provides focused retrieval with comprehensive context.

# 4.7.5 Long-context prompting versus RAG/document-graph architectures

A recurring architectural question is whether a team should build a retrieval layer at all when modern language models can accept very large prompts. Long-context prompting and RAG solve overlapping but different problems. Long-context prompting is attractive when the relevant evidence set is small, static, and already known. RAG is preferable when the corpus is large, frequently updated, access-controlled, or must produce reproducible citations and audit trails. In practice, strong systems often combine both: retrieval narrows the candidate evidence set, and a long-context model synthesizes the selected passages.
