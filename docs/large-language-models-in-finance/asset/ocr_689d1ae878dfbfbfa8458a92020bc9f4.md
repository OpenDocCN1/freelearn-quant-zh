# **Final-phase update: Delegated financial agents**

A compact refinement from the agentic-finance framework is to separate *proposal* from *institutional action*. The useful production object is not an unconstrained chatbot, but a delegated decision system whose stochastic component proposes and whose external controls decide whether the proposal can become an institutional commitment. A minimal controlled-evidence chain is

```
$$H_t \xrightarrow{\rho_t} b_t \xrightarrow{\pi_t} A_t^e \xrightarrow{\Pi_t} A_t \xrightarrow{E_t} S_{t+1} \xrightarrow{M_t} H_{t+1}.$$
```

Here $H_t$ is the replayable history, $\rho_t$ forms the controlled belief state, $\pi_t$ is the LLM-centered proposal policy, $A_t^e$ is the proposed action, $\Pi_t$ is the external admissibility projection or shield, $A_t$ is the accepted action, $E_t$ is the permissioned execution adapter, and $M_t$ writes memory and audit evidence. The projection $\Pi_t$ is not a prompt, a system message, or a politely worded instruction. It is a *shield* in the sense of Alshieikh et al. [2018]: a correct-by-construction filter evaluated outside the learned policy, which cannot be argued with by the policy, and which rejects an inadmissible proposal rather than asking the policy to reconsider it. This distinction is the difference between a system that is usually safe and a system whose safety does not depend on the model's mood.

Figure 5.1 draws the contract, and the important feature of that diagram is an absence: no arrow bypasses $\Pi_t$.

The practical rule is simple: the model may draft research, recommend a structured portfolio intent, or flag an exception, but market orders, client recommendations, limit changes, regulatory submissions, and entitlement changes require the appropriate shield, approval, and audit path before execution [Noguer i Alonso et al., 2026, Noguer i Alonso and Pacheco Aznar, 2026].

# A multi-agent system includes:

+   - a communication protocol, specifying how messages are routed and interpreted;
+   - an organizational structure (e.g., hierarchical, peer-to-peer, hub-and-spoke);
+   - shared or distributed memory components; and
+   - possibly external controllers or orchestrators that manage agent lifecycles and interactions.

For the running research workstation, the set $\mathcal{M}$ contains at least the Research Analyst, Data Analyst, Risk Compliance, and Orchestrator agents. The orchestrator is not just a convenience wrapper: it defines the order of work, decides when intermediate results are sufficient, determines which evidence is passed from one agent to another, and records the final handoff to the human portfolio manager.

In financial contexts, multi-agent systems arise naturally. For example, a research assistant may coordinate agents specialized in company fundamentals, macroeconomic conditions, and alternative data; a risk assistant may orchestrate agents that query limits, stress scenarios, and regulatory requirements. Here, no single agent has the full picture—the outcome depends on how these agents exchange information and build on each other's outputs.
