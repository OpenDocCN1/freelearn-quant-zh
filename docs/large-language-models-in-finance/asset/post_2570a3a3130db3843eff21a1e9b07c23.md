## 14.1 Beyond prediction

The integration of large language models (LLMs) into finance has often been framed as a predictive challenge: forecasting stock movements, estimating credit default probabilities, or anticipating market sentiment [Sezer et al., 2020, Zhang et al., 2024b]. These applications are important, but they represent only one layer of a broader transition. The emerging frontier is a shift from systems that produce an estimate to systems that maintain state, pursue a goal, call tools, evaluate constraints, and take actions inside a governed workflow [Wang et al., 2024, Xi et al., 2025, Yao et al., 2023b, Schick et al., 2023].

Prediction and agency should not be conflated. A credit model can estimate the probability that a borrower breaches a covenant. An agentic credit workflow must additionally determine which documents are authoritative, retrieve the relevant covenant language, reconcile contradictory data, simulate possible interventions, check approval limits, request human authorization when required, execute an admissible action, and preserve an audit trail. Increasing the parameter count of the predictor does not, by itself, supply persistent memory, permissions, transaction semantics, or institutional accountability.

This broader evolution creates opportunities for faster analysis, more adaptive products, and lower operational friction. It also creates risks that are endogenous to deployment: model-generated actions alter prices, liquidity, counterparties’ incentives, and the information available to other agents. Consequently, the relevant object is not an isolated model but a socio-technical system embedded in a market [Daníelsson et al., 2022].

The chapter develops three connected themes:

- 1. **The rise of agentic finance.** The architectural and cognitive transition from instruction-following models to goal-seeking systems operating under explicit delegation boundaries.
- 2. **Generative Alpha.** Potential value derived from searching over strategies, contracts, execution policies, and market designs rather than merely forecasting a pre-existing target.
- 3. **Systemic risk among interacting agents.** The possibility that shared models, common data, feedback, and strategic interaction amplify shocks or reduce effective market diversity.

## 14.2 The architecture of autonomous financial agents

The transition from predictive LLMs to autonomous agents is not merely a matter of scale; it requires a different systems architecture. A useful financial agent combines a reasoning model with memory, planning, tools, deterministic controls, and a mechanism for learning from outcomes. It should be understood as a bounded decision system rather than as an unconstrained LLM [Wang et al., 2024, Shinn et al., 2023].

Consider a portfolio-monitoring example. A large predictive model may rank securities by expected return. A deployable agent must also maintain the portfolio's current exposures, identify which data were available at the decision time, retrieve mandate restrictions, generate alternative trades, estimate transaction costs and market impact, reject actions that violate limits, obtain approval for high-impact decisions, submit an order through a sandboxed interface, and compare realized execution with the plan. These requirements explain why architectural change is necessary beyond simply increasing model size.

### 14.2.1 Core components of an agentic architecture

An autonomous financial agent can be represented as a collection of interconnected modules whose authorities are explicitly separated.

Definition 14.2.1 (Autonomous financial agent). A bounded autonomous financial agent is a composite system

```
\mathfrak{A} = \langle \mathcal{R}, \mathcal{M}, \mathcal{P}, \mathcal{T}, \mathcal{L}, \mathcal{G} \rangle, \quad (14.1)
```

where:

- \(\mathcal{R}\) is the core reasoning or proposal engine;
- \(\mathcal{M}\) is the memory and belief-state system;
- \(\mathcal{P}\) is the planning and goal-decomposition module;
- \(\mathcal{T}\) is the typed tool-use and action interface;
- \(\mathcal{L}\) is the evaluation, reflection, and learning module; and
- \(\mathcal{G}\) is the governance layer containing permissions, risk limits, validation rules, approval requirements, and audit controls.

The agent is autonomous only within the admissible action set defined by \(\mathcal{G}\).

#### The core reasoning engine

The core engine interprets a high-level objective, summarizes evidence, proposes intermediate steps, and produces structured candidate actions. It can be a dense model or, in some deployments, a Mixture-of-Experts (MoE) model [Fedus et al., 2022]. MoE architectures can be useful because sparse routing allows different experts to specialize in domains such as accounting language, legal clauses, market microstructure, code, or risk analysis while activating only a subset of parameters for each token. This can increase effective capacity without requiring every parameter to be evaluated on every step. The advantage is operational rather than magical: routing must be monitored, expert specialization can be uneven, and an MoE does not replace the external controls required for financial decisions.

```
\mathcal{R} : \mathcal{X} \times \mathcal{B} \times \mathcal{Q} \longrightarrow \mathcal{Z}, \quad (14.2)
```

where \(\mathcal{X}\) is the current observation space, \(\mathcal{B}\) is the belief state supplied by memory, \(\mathcal{Q}\) is the goal or query space, and \(\mathcal{Z}\) is a space of proposed plans or structured actions. The output is a proposal, not automatically an executable order.

#### Long-term memory and belief state

Autonomous workflows require memory beyond a single prompt. Semantic memory stores retrievable representations of reports, policies, and prior cases; structured memory records positions, limits, approvals, and transaction state; episodic memory preserves previous decisions and outcomes. Retrieval-augmented generation provides one mechanism for grounding the reasoning engine in external evidence [Lewis et al., 2020].

```
Algorithm 19 Auditable memory update protocol
Input: New information i_new, belief state B_t, provenance metadata q_t
Output: Updated belief state B_{t+1} and audit record a_t
Validate source, timestamp, permissions, and document version
Encode i_new as representation v_new
Retrieve candidate memories M_rel <- kNN(v_new, M)
Compute consistency and freshness scores for i_new relative to M_rel
if source validation fails then
    Quarantine i_new and preserve the failure reason
else if material conflict is detected then
    Escalate for reconciliation; do not silently overwrite B_t
else
    B_{t+1} <- integrate(B_t, i_new, q_t)
end if
Append provenance, retrieval links, and update decision to a_t
return B_{t+1}, a_t
```

#### Planning, tools, reflection, and governance

The planning module converts a goal into a sequence of verifiable subgoals. The tool layer exposes typed operations—for example, retrieving a filing, running a pricing library, querying a position database, or submitting a paper-trading order. Typed schemas matter because free-form text is not a safe transaction protocol. The reflection module compares expected and realized outcomes, records failures, and proposes improvements. Finally, the governance layer determines whether a proposed action is permitted, requires human approval, or must be rejected.

Figure 14.1 can be read from top to bottom. Market and institutional inputs enter the memory, planning, and reasoning layers with provenance attached. Memory and planning interact iteratively with the reasoning engine to produce a structured proposal. The policy and risk gate then checks mandates, limits, permissions, and approval requirements before any tool can act. Approved tool calls reach only a controlled execution environment. Execution outcomes flow back to evaluation and memory, creating a learning loop without allowing the language model to bypass the control boundary.
