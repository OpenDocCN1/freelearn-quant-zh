## 技术质量契约

本书始终采用一种简单的纪律：每个重要的金融 LLM 理念都应同时在四个层面上可读。首先，它应由真实的金融工作流程所驱动。其次，它应由精确的数学对象表示。第三，它应映射到可实现的算法或软件模式。第四，它应具有在系统投入生产前就能检测故障的评估和治理协议。

明确包含本契约的原因是，金融 AI 项目常常在这些层级之间的接口处失败。一个技术上优雅的模型可能会因数据划分泄露未来信息而失败。一个编写良好的提示词可能会因工具权限在模型外未被强制执行而失败。一个强大的检索系统可能会因答案未针对检索到的证据逐条核查声明而失败。相反，如果工作流程清晰、数据干净、权限确定性且评估协议诚实，一个普通模型也可能很有价值。

## 四层标准

针对本书开发的每个架构，预期的标准如下：

- 1. **动机。** 在模型之前阐明金融决策问题。读者应知道该系统是支持研究、风险、交易、合规、客户服务、运营还是治理。

- 2. **数学。** 在陈述保证之前，定义输入、输出、损失函数、信息集、时间戳、可接受的动作以及不确定性模型。

- 3. **代码。** 提供具有类型、可审计、尽可能确定性的代码，并明确区分什么是可运行的参考实现，什么是依赖生产环境的集成。

- 4. **验证。** 在模拟部署环境的协议下，测量任务质量、校准、泄露、忠实性、延迟、成本以及控制失败。

实际后果是，本书避免将 LLM 响应视为原始对象。只有当响应与证据关联、在允许的策略下生成、针对相关数值和文本约束进行检查，并记录在可复现的审计轨迹中时，才可接受。

## 数学纪律

每当结果涉及金融部署时，默认对象不是静态数据集，而是时间索引的实验。数据点写作：

$$z_i = (x_i, y_i, \tau_i, g_i), \quad (1)$$

其中 $x_i$ 是输入，$y_i$ 是目标或审阅者判断，$\tau_i$ 是可用时间，$g_i$ 是可选的分组变量，例如发行人、投资组合、交易台、司法管辖区或产品系列。在决策时间 $t$ 进行的有效评估只能使用可用时间不晚于 $t$ 的工件。

标准监督目标为：

$$\widehat{\theta} \in \arg \min_{\theta \in \Theta} \frac{1}{|\mathcal{I}_{train}|} \sum_{i \in \mathcal{I}_{train}} w_i \ell(f_\theta(x_i), y_i) + \lambda \Omega(\theta; \theta_0), \quad (2)$$

其中权重 $w_i$ 考虑类别不平衡、交易台优先级或成本不对称，$\Omega(\theta; \theta_0)$ 控制偏离基模型的程度。评估集并非随意的事后想法：它是由时间、分组和可用性约束决定的正式对象。

对于生成式系统，质量是向量值的。金融 LLM 不仅由 ROUGE、BLEU、余弦相似度或双偏好等语义指标来评判。它由以下元组评判：

$$Q = (Q_{\text{task}}, Q_{\text{faith}}, Q_{\text{num}}, Q_{\text{cal}}, Q_{\text{policy}}, Q_{\text{lat}}, Q_{\text{cost}}), \quad (3)$$

涵盖任务实用性、证据忠实性、数值一致性、校准、策略合规性、延迟和成本。这就是后续章节反复将模型指标与治理指标相结合的原因。

### 代码纪律

伴随代码遵循五条规则：

- 1. **类型化边界。** 尽可能使用显式数据结构而非自由形式的字典来表示输入、输出、证据项、工具调用和声明。

- 2. **默认拒绝。** 如果时间戳、权限、引用、架构或数值检查无法验证，参考模式会拒绝或升级，而非静默继续。

- 3. **无隐藏的未来信息。** 索引构建、提示词示例、标签和评估工件必须通过可用时间审计。

- 4. **确定性测试。** 最小示例足够小，可在持续集成中运行，且不依赖私有基础设施。

- 5. **关注点分离。** 检索、生成、工具执行、策略检查和审计日志是独立的函数；提示词不作为访问控制的替代品。

### 解释纪律

金融 AI 中的高质量解释必须告诉读者该方法为何需要、什么假设使其有效、它如何可能失败，以及如何检测该失败。因此，章节采用重复模式：从金融痛点入手，引入数学抽象，展示可实现的模式，然后陈述验证或治理挂钩。这也是向模型风险、合规、法务、投资和技术利益相关方展示内部金融 AI 项目的推荐方式。

### 符号和缩写

本节固定书中反复使用的符号。符号刻意设计为可操作的：选择符号，以便直接映射到代码工件，如数据集、提示词、检索索引、工具、策略和审计日志。

| 符号或术语 | 含义 |
| :--- | :--- |
| LLM | 大型语言模型。 |
| RAG | 检索增强生成：基于检索证据的生成管道。 |
| MCP | 模型上下文协议：一种标准的主机-客户端-服务器协议，用于将 LLM 应用程序连接到资源、提示词和工具。金融授权和治理仍然是实现义务。 |
| D | 数据集或文档语料库。在经验部分，$D_{\le t}$ 表示仅在决策时间 $t$ 可用的工件。 |
| X, Y | 输入和输出空间。对于分类，$x \in X$ 是文本或特征对象，$y \in Y$ 是其标签。 |

| 符号 | 描述 |
| :--- | :--- |
| $\ell(\hat{y}, y)$ | 任务损失。示例包括分类的交叉熵、回归的平方误差以及基于生成的声明级支持损失。 |
| $R(\theta)$ 和 $\hat{R}(\theta)$ | 模型参数 $\theta$ 的总体风险和经验风险。 |
| $\mathcal{F}_t$ | 过滤：截至时间 $t$ 可用的信息。这是“无未来信息”背后的正式对象。 |
| $\mathcal{F}_t^{MCP}$ | 工作流在 MCP 延迟、授权、删减和带宽约束后可用的信息。 |
| $A_i$ | 从生成答案中提取的原子声明。 |
| $E_i$ | 为声明 $A_i$ 检索到的证据包，包括文档标识符、时间戳和段落。 |
| $E_i \vDash A_i$ | 在指定验证器和可接受语料库下，证据包 $E_i$ 支持声明 $A_i$。 |
| Faith($a, E$) | 声明级忠实度分数：答案 $a$ 中由证据 $E$ 支持的实质性声明的比例。 |
| Gate | 策略门控，将拟议的工具调用和状态映射为允许、拒绝或升级。 |
| $\pi_\theta$ | 具有参数 $\theta$ 的模型或代理策略。在交易场景中，它将信息状态映射到动作；在 LLM 场景中，它将提示词和上下文映射到令牌/动作分布。 |
| $V(t, x)$ | 动态规划公式中的值函数。 |
| $\Delta f$ | 微分隐私中函数的敏感度。 |
| $\epsilon, \delta$ | 微分隐私参数。 |
| $\lambda$ | Kyle 风格价格影响系数；特定于模型，而非通用熵变换。 |
| 人工监督 | 一种具有明确责任、证据审查、升级权限以及覆盖/开关机能力的控制过程。 |

**实现约定。** 伴随代码使用相同的概念对象。`Document` 对应 $\mathcal{D}$ 的一个元素；`Claim` 对应 $A_i$；`ToolCall` 是由 `Gate` 评估的候选动作；审计记录存储了复制重要输出所需的模型、提示词、语料库、工具和策略版本。
