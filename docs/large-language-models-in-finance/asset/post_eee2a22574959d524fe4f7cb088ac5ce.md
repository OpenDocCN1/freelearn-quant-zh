
## Memory and computational optimizations

Large-scale financial transformer models require sophisticated memory and computational optimizations to enable practical deployment within the typical infrastructure constraints of financial institutions. Gradient checkpointing trades computation for memory by recomputing intermediate activations during the backward pass rather than storing them throughout the forward pass. This technique enables training of significantly larger models within memory constraints, albeit with increased training time.

The mechanics of gradient checkpointing are best understood by examining how activations are selectively stored and recomputed during training. The following pseudocode illustrates the forward and backward passes under a checkpointing strategy:

```
Algorithm 1 Gradient checkpointing for transformer layers

Forward pass:
for l = 1 to L do
  if l is checkpoint layer then
    Store x_l in memory
  end if
  x_{l+1} = TransformerLayer_l(x_l)
end for

Backward pass:
for l = L to 1 do
  if l is checkpoint layer then
    Retrieve x_l from memory
  else
    Recompute x_l from previous checkpoint
  end if
  Compute gradients for layer l
end for
```

The takeaway is simple: gradient checkpointing reduces GPU memory use because not every activation has to be stored during the forward pass. The cost is extra computation during backpropagation, because some activations must be recomputed before their gradients can be evaluated. In practice, this trade-off is often attractive when memory, rather than arithmetic throughput, is the binding constraint.

Parameter-sharing strategies reduce model size while maintaining expressivity. Weight tying between the embedding and output layers is particularly effective for financial models, where vocabulary and output distributions often share similar structures. Advanced sharing strategies include cross-layer parameter sharing and attention head sharing within layers.

Beyond parameter efficiency, scaling also requires distributing computation across hardware resources. Model parallelism enables training and inference of models whose size exceeds a single device’s memory capacity. Pipeline parallelism divides model layers across multiple devices, while tensor parallelism distributes individual operations. Hybrid parallelism strategies often prove optimal, combining pipeline and tensor parallelism according to the model architecture and available hardware. The Megatron-LM framework provides sophisticated parallelism implementations specifically designed for transformer architectures [Shoeybi et al., 2019]. Financial institutions have successfully deployed Megatron-based models with hundreds of billions of parameters across GPU clusters for comprehensive market analysis and risk assessment applications.

In addition, numerical optimization plays an important role in deployment efficiency. Quantization techniques reduce model memory requirements and inference latency while maintaining acceptable performance levels. Post-training quantization converts trained models to lower-precision representations (typically int8 or int4), whereas quantization-aware training incorporates quantization effects during training to improve accuracy retention. In finance, mixed-precision quantization often provides optimal trade-offs, maintaining higher precision for critical numerical computations while using lower precision for attention weights and feed-forward computations:

```
MixedPrecision(x) = \begin{cases} \text{FP16}(x) & \text{if } x \in \mathcal{N} \text{ (numerical operations)} \\ \text{INT8}(x) & \text{if } x \in \mathcal{A} \text{ (attention weights)} \\ \text{FP32}(x) & \text{if } x \in \mathcal{C} \text{ (critical computations)} \end{cases} (2.17)
```

Together, these architectural and engineering strategies define how large financial language models are built and deployed. Yet none of this machinery operates directly on text; it operates on numerical representations. To understand the full pipeline, we must now examine how financial language is converted into tokens and embeddings.

## 2.2 Tokenization and embeddings

Tokenization forms the critical bridge between raw text and neural network inputs. Tokenization strategies must balance vocabulary size with the need to accurately represent domain-specific terms, numerical values, and symbols. In this section, we examine how financial text is tokenized, mapped to vector representations, and organized into vocabularies.

### 2.2.1 Subword tokenization approaches

Modern LLMs employ subword tokenization algorithms that decompose words into smaller units, enabling the model to handle out-of-vocabulary terms while maintaining reasonable vocabulary sizes. This is especially relevant in financial text, where specialized terminology and evolving entity names are common, yet vocabulary size must remain computationally tractable. Subword methods, therefore, strike a balance between expressivity and efficiency, determining how granularly language is represented before it reaches the embedding layer. The following approaches illustrate how different subword strategies construct and optimize vocabularies.

### Byte-pair encoding (BPE)

BPE [Sennrich et al., 2016] iteratively merges the most frequent pairs of characters or character sequences:

```
Algorithm 2 BPE algorithm
Initialize vocabulary with individual characters
while vocabulary size < target do
  Find most frequent adjacent pair
  Merge pair into single token
  Add to vocabulary
end while
```

For example, the word "EBITDA" might be tokenized as ["EBI", "TD", "A"] initially, but after observing it frequently in financial texts, BPE would learn to treat "EBITDA" as a single token.

### WordPiece

WordPiece [Schuster and Nakajima, 2012], used by BERT and its variants, selects merges that maximize the likelihood of the training data rather than simple frequency:

\(\text{score}(x, y) = \frac{\text{freq}(xy)}{\text{freq}(x) \times \text{freq}(y)}\)

This approach tends to create more linguistically meaningful subwords and handles morphological variations effectively.

### SentencePiece

SentencePiece [Kudo and Richardson, 2018] treats the input as a raw stream of Unicode characters, not requiring pre-tokenization. This language-agnostic approach is particularly valuable for multilingual financial models that need to process documents in multiple languages with different writing systems.

Financial texts present distinctive tokenization challenges that require specialized handling. Currency symbols and formats must be represented consistently, including symbols such as $, €, ¥, and £, as well as compact numerical formats like $1.2B, €500M, or ¥1,234,567. Percentages and basis point expressions, such as 15.3% or 25bps, introduce additional formatting conventions that tokenizers must process without fragmenting meaning.

Company identifiers introduce further complexity. Stock tickers such as AAPL, MSFT, and GOOGL function as semantically dense tokens, while structured identifiers such as CUSIP and ISIN codes or **Legal Entity Identifiers (LEIs)** follow rigid alphanumeric patterns. Improper tokenization of these identifiers can distort entity recognition and downstream analysis.

Financial writing also relies heavily on abbreviations and technical shorthand. Terms such as EBITDA, P/E, ROE, ROA, and EPS encode compact financial concepts, while period comparisons such as YoY, QoQ, and MoM and valuation terms such as DCF, NPV, and IRR carry domain-specific semantics that should ideally be preserved as cohesive units rather than fragmented subwords.
