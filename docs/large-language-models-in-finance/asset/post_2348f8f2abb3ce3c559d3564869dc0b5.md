## Reported empirical behavior

In backtests on a small set of U.S. equities over a limited historical period, Yu et al. [2023] reported that FinMem:

- Outperforms deep RL baselines and buy-and-hold on several assets, particularly those with strong trends and rich news flow;
- Achieves these results with shorter training windows than DRL baselines; and

While the performance is dependent on asset and period, the experiments are limited in scope. Nonetheless, they provide evidence that explicit memory structures can stabilize LLM-based trading agents.

## 12.2.2 TradingAgents: Debate-based multi-agent trading

TradingAgents [Xiao et al., 2025] introduce a debate-based framework in which several LLM agents examine the same market situation from different professional perspectives. The design mirrors a human investment committee: one participant gathers evidence, another proposes a trade, and another challenges the proposal from a risk-control perspective. This role separation is useful because it makes the reasoning process more auditable than a single monolithic prompt.

The framework uses distinct LLM agents playing roles such as:

- Analysts, who interpret news and fundamentals;
- Traders, who propose position changes; and
- Risk managers, who critique and constrain proposals.

## Markov game formulation

A Markov game generalizes an MDP from one decision maker to several interacting decision makers. At each time step, the environment has a state, each agent receives an observation, each agent proposes an action or recommendation, and the system combines these proposals into an outcome. In trading applications, this formalism is useful even when the agents are not truly strategic in the game-theoretic sense: it forces us to specify what each role observes, what it is allowed to recommend, and how conflicts are resolved. Formally, we can view a debate-based trading system as a Markov game with:

- a global state \( s_t \) containing market variables, news, current positions, and risk limits;
- per-agent observations \( o_t^k = g_k(s_t) \), where each observation map \( g_k \) selects the information relevant to role \( k \);
- per-agent policies \( \pi_{\theta_k}(a_t^k \mid o_t^k) \) for \( k = 1, \dots, K \), producing role-specific proposals or critiques; and
- a coordination mechanism that aggregates agent outputs into a final trading action \( a_t \) or into an escalation decision for human review.

A stylized aggregation rule is as follows:

\( a_t^* = \arg \max_{a \in \mathcal{A}} \sum_{k=1}^K w_k q_k(a; s_t) \),

where \( q_k(a; s_t) \) is a score produced by agent \( k \) for action \( a \) given state \( s_t \), and \( w_k \) reflects the agent's authority or role weight (e.g. risk manager vs trader).

**Implementation sketch.** The following repository-style skeleton shows how the aggregation rule in Equation (12.11) can be implemented without treating the code block as a numbered object. It aggregates multiple LLM-based agent proposals into a single trading action and performs a simple policy-gradient style update:

```python
def aggregate_actions(agent_outputs, role_weights):
    # agent_outputs: list of dicts with {'action': a, 'score': q, 'role': r}
    aggregated_scores = defaultdict(float)
    for out in agent_outputs:
        a = out["action"]
        q = out["score"]
        w = role_weights[out["role"]]
        aggregated_scores[a] += w * q
    # pick action with highest weighted score
    return max(aggregated_scores.items(), key=lambda x: x[1])[0]

for epoch in range(num_epochs):
    for episode in range(num_episodes):
        state = env.reset()
        done = False
        traj_log_probs = []
        traj_rewards = []

        while not done:
            agent_outputs = []
            for agent in agents: # analyst, trader, risk_manager, ...
                prompt = build_agent_prompt(agent, state)
                action, score, log_prob = agent.propose_action(prompt)
                agent_outputs.append(
                    {"action": action, "score": score, "role": agent.role,
                     "log_prob": log_prob}
                )

            final_action = aggregate_actions(agent_outputs, role_weights)
            next_state, reward, done, info = env.step(final_action)

            # store log-probs for all agents to shape their updates
            traj_log_probs.append([out["log_prob"] for out in agent_outputs])
            traj_rewards.append(reward)
            state = next_state

        # compute returns / advantages and update agents jointly
        advantages = compute_advantages(traj_rewards, gamma, lam)
        for agent_idx, agent in enumerate(agents):
            loss = 0.0
            for t, A_t in enumerate(advantages):
                loss -= traj_log_probs[t][agent_idx] * A_t
            agent.optimizer.zero_grad()
            loss.backward()
            agent.optimizer.step()
```

Again, this is a schematic pattern. Real systems require more nuanced reward shaping, coordination, tool access, audit logging, transaction-cost modeling, and safety checks before any live deployment.

## Reported empirical behavior

On a short out-of-sample period for a small set of large-cap equities, Xiao et al. [2025] found that the multi-agent system:

- Achieves cumulative returns above buy-and-hold and simple technical baselines;
- Exhibits high Sharpe ratios over the tested window, partly due to the absence of large drawdowns; and
- Benefits materially from the risk-manager agent, which reduces exposure around high-risk events.

The authors explicitly caution that the short horizon and unusually benign conditions limit the generality of these Sharpe estimates.

## 12.2.3 FinCon and FinAgent: Portfolio-level multi-agent systems

FinCon [Yu et al., 2024] and FinAgent [Zhang et al., 2024a] extend the multi-agent paradigm beyond a single trading decision. FinCon emphasizes portfolio-level coordination and risk-aware objectives, while FinAgent emphasizes multimodal and tool-augmented inputs.

## FinCon: CVaR-aware portfolio agent

FinCon coordinates multiple asset-level agents through a portfolio agent optimized for CVaR-aware objectives. Let \(w_t \in \mathbb{R}^d\) denote portfolio weights, \(\Delta p_{t+1}\) the price changes, and \(\text{PnL}_{t+1} = w_t^\top \Delta p_{t+1}\) the one-step profit and loss. Over a horizon of \(T\) steps, we define:

\(\text{PnL} = \sum_{t=0}^{T-1} \text{PnL}_{t+1}.\)

The portfolio agent seeks to maximize:

\(J(\theta) = \mathbb{E}[\text{PnL}] - \lambda \text{CVaR}_\alpha(L), \quad L := -\text{PnL}, \quad (12.12)\)

where the risk term is applied to the *loss* \(L = -\text{PnL}\), not to PnL itself. The distinction is not cosmetic. Under the standard upper-tail convention, \(\text{CVaR}_\alpha\) is the mean of the worst \((1-\alpha)\) tail of its argument; applied directly to PnL it would penalize the agent for making large *profits*, which inverts the sign of the intended objective. Writing the risk term in losses is what makes (12.12) a risk-averse objective rather than a profit-averse one.

For optimization, the useful form is the Rockafellar–Uryasev variational representation:

\(\text{CVaR}_\alpha(L) = \min_{\nu \in \mathbb{R}} \left\{ \nu + \frac{1}{1-\alpha} \mathbb{E}[(L - \nu)_+] \right\}. \quad (12.13)\)

**What is and is not convex here.** The right-hand side of (12.13) is jointly convex in \((\nu, u)\) whenever the loss \(L\) is convex in the decision variable \(u\) — which holds for portfolio weights under a linear P&L map, and is the setting in which Rockafellar and Uryasev state the result. It does *not* hold when the decision variable is the parameter vector \(\theta\) of a neural policy: \(L\) is then a non-convex function of \(\theta\), and the composite problem is non-convex however the risk measure is written. For a neural policy, (12.13) is a *differentiable, sample-based surrogate* with a well-defined subgradient, not a convex program. Claiming convexity here is a common and consequential slip: it licenses convergence guarantees that do not hold.

Optimize \(\nu\) jointly with \(\theta\) on the sample objective

\(\widehat{J}(\theta, \nu) = \widehat{\mathbb{E}}[\text{PnL}_\theta] - \lambda \left( \nu + \frac{1}{1-\alpha} \widehat{\mathbb{E}}[(L_\theta - \nu)_+] \right), \quad (12.14)\)

Any minimizer \(\nu^\star\) is an \(\alpha\)-quantile of \(L\); when the distribution of \(L\) is continuous at that quantile the minimizer is unique and equals the usual \(\text{VaR}_\alpha(L)\). With atoms — which discrete scenario sets always have — the set of minimizers can be an interval, and any point in it is admissible. The \(\theta\)-gradient of the risk term is supported on the tail — it is weighted by the indicator \(\mathbf{1}\{L_\theta > \nu\}\) — which is precisely what makes it a CVaR gradient.
