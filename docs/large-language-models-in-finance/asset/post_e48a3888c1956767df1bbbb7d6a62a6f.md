
```
precision = tp / (tp + fp) if tp + fp else 0.0
recall = tp / (tp + fn) if tp + fn else 0.0
f1 = 2 * precision * recall / (precision + recall) if precision + recall else 0.0
return {"precision": precision, "recall": recall, "f1": f1,
       "tp": tp, "fp": fp, "fn": fn}
```

## 15.8 Reproducibility protocol for empirical financial LLM studies

A financial LLM study should be reproducible at the level of data provenance, temporal splits, model versions, prompt versions, retrieval-corpus versions, and evaluation scripts. The following protocol is the minimum standard assumed by the empirical examples in this book.

- 1. **Data card.** State the data source, license, timestamp, survivorship policy, document universe, preprocessing rules, and any exclusion criteria.
- 2. **Temporal split.** Use walk-forward or strictly chronological train/validation/test partitions. No document, label, embedding, prompt example, or retrieval chunk dated after the decision time may enter the model context.
- 3. **Model card.** Record the base model, tokenizer, fine-tuning method, quantization, context window, inference parameters, and safety filters.
- 4. **Prompt and retrieval versioning.** Hash prompt templates, tool schemas, vector indexes, chunking policies, rerankers, and retrieved evidence bundles.
- 5. **Metrics.** Report task metrics and governance metrics: accuracy or F1, calibration, citation faithfulness, numerical consistency, refusal accuracy, escalation precision, latency, cost, and failure examples.
- 6. **Uncertainty.** Provide confidence intervals or bootstrap intervals where sampling variation matters, and separate illustrative examples from audited empirical results.
- 7. **Audit log.** Store the model version, prompt version, retrieved document identifiers, tool-call parameters, human approvals, and final output hash for every material run.

A companion implementation can follow the following directory structure:

```

  data_card.md
  build_index.py
  evaluate_faithfulness.py
 financial_sentiment/
  temporal_split.py

  contamination_checks.py
  timestamp_audit.py

prompt_registry/

```

The central rule is simple: no result should be presented as empirical evidence unless a reader can identify what information was available at the decision time and reproduce the evaluation path from raw input to reported metric.

## 15.9 Reference implementation standard

The official companion repository is Packt's official _LLMs in Finance_ repository. It is not intended to be a full production platform. Its purpose is narrower and more important: to provide small, auditable, reference implementations of the invariants used throughout the book. For this edition, the reproducibility identifier is tag `B32413-v1.0.0` at commit `c80ddc04d29fc2ec245bd7bda03c6833e2b2392e`. The submission includes both a source archive and a complete immutable Git bundle for that tag. The official Packt repository should mirror the exact tag and commit; the default branch is not a reproducibility identifier.

A reference implementation is considered acceptable only if it satisfies the following checklist:

- 1. all externally visible objects have typed schemas;
- 2. timestamp checks are explicit and fail closed;
- 3. retrieval returns evidence identifiers, not anonymous text blobs;
- 4. material claims can be linked to evidence identifiers;
- 5. tool calls pass deterministic authorization before execution;
- 6. evaluation scripts compute both task metrics and governance metrics;
- 7. tests run without private credentials or proprietary data.

In the tagged release, the directory `companion/src/finllm` implements this checklist in dependency-light Python so that the logic remains inspectable. Its components include typed document, claim, tool-call, version, and audit objects; a deterministic retrieval smoke test; timestamp-leakage checks; claim-support scoring; calibration metrics; and guarded tool execution. These are not substitutes for enterprise systems; they are executable specifications of the design principles used in the manuscript. The directory companion/experiments/rag_sec_filings contains a credential-free smoke benchmark with fictional filings, questions, a runnable script, a results table, and an audit log.

The directory companion/experiments/pit contains the Chapter 13 generator, machine-readable book results, the seed-11 run, and the declared 60-seed drift decomposition. These benchmarks test reproducibility and governance; they are not evidence of live market forecasting performance.

The most important mathematical invariant enforced by the reference implementation is

$a_j \le t$ for every evidence item $d_j$ used at decision time $t$.

If this inequality fails for any retrieved item, the pipeline should reject the run. This single inequality is the operational form of the no-lookahead propositions in Chapters 3, 4, and 14.

### Listing 15.6: Minimal use of the companion package

```
from datetime import datetime, timezone
from finllm.contracts import Claim, Document, EvidenceBundle
from finllm.rag import faithfulness_score, retrieve_by_bm25_like
from finllm.temporal import assert_documents_available

now = datetime(2026, 7, 1, tzinfo=timezone.utc)
corpus = (
    Document(
        document_id="filing-001",
        text="Revenue increased by 8 percent in fiscal 2025.",
        source="10-K",
        timestamp=datetime(2026, 2, 15, tzinfo=timezone.utc),
    ),
)
assert_documents_available(corpus, decision_time=now)
evidence = retrieve_by_bm25_like("How did revenue change?", corpus, k=3)
claim = Claim(text="Revenue increased by 8 percent.")
print(faithfulness_score([EvidenceBundle(claim, evidence)]))
```

The example is intentionally small and uses the interface implemented by the tagged companion release. It captures the essential production habit: the system stores evidence identifiers, checks availability times, retrieves from a valid corpus, and evaluates whether claims are cited. A more sophisticated implementation may use dense embeddings, hybrid search, cross-encoder re-ranking, claim-level natural-language inference, and immutable audit storage; the invariant remains the same.
