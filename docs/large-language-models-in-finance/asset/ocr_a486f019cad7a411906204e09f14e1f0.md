# 12.7 From illustrative examples to audited empirical evidence

The empirical standard for financial LLMs should be higher than “the model produced a plausible answer.” A result becomes credible only when the information set, benchmark, metric, and failure analysis are explicit. This book therefore distinguishes four levels of empirical evidence.

+   1. **Illustrative example:** a single example used to explain a method. It may be useful pedagogically but should not be cited as evidence of performance.
+   2. **Reproducible smoke test:** a deterministic script with fixed inputs and expected outputs. It catches broken code paths but does not establish financial value.
+   3. **Benchmark experiment:** a documented dataset, temporal split, model version, prompt version, and metric suite. It supports comparative claims within the benchmark’s scope.
+   4. **Audited deployment evidence:** production or pilot evidence with logged decisions, review outcomes, confidence intervals, failure cases, human overrides, and post-deployment monitoring.

A strong empirical table should therefore report not only accuracy or F1, but also the maturity level of the evidence. For example, a RAG experiment over filings should state the filing universe, timestamp cutoff, retrieval index hash, chunking policy, citation-faithfulness metric, number of expert-reviewed answers, confidence interval, and number of high-severity failures. A time-series LLM experiment should state the walk-forward split, rebalancing schedule, transaction-cost assumptions, survivorship policy, hyperparameter-selection window, and whether benchmark contamination checks were run.

**Proposition 12.7.1** (Minimum evidence condition for performance claims). _A financial LLM performance claim is auditable only if a reviewer can reconstruct the tuple_

```
`(D_{<=t}, f_\theta, p, r, m, \ell, \mathcal{A}),`
```

_where_ \(\mathcal{D}_{\le t}\) _is the admissible data,_ \(f_\theta\) _is the model, p is the prompt or policy template, r is the retrieval index and corpus version, m is the metric,_ \(\ell\) _is the loss or scoring rule, and_ \(\mathcal{A}\) _is the audit log. Without this tuple, the claim may still be a useful illustration, but it is not reproducible evidence._

_Proof._ Changing any component of the tuple can change the measured result: the data determine what information was available; the model and prompt determine the mapping from information to output; the retrieval version determines the evidence visible to the generator; the metric and loss determine what is being rewarded; and the audit log determines whether the run can be reconstructed. If any component is missing, two reviewers cannot determine whether they are evaluating the same experiment.
