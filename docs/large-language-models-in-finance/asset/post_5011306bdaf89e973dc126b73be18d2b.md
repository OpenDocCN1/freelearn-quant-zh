

## 15.5 Financial data resources

Financial LLM development depends on reliable datasets for training, evaluation, retrieval, and benchmarking. This section summarizes public financial NLP datasets, market data sources, and simple access patterns for market data and SEC filings.

### 15.5.1 Public financial datasets

Financial PhraseBank should be reported together with the selected annotator-agreement split [Malo et al., 2014, Hugging Face, 2026]. FiQA refers to a family of financial opinion mining and question-answering benchmarks, so the exact version and split should always be stated [Maia et al., 2018]. FinEAS is a model and code resource for financial sentiment and sentence embeddings rather than a raw benchmark dataset [Gutiérrez-Fandiño et al., 2021].

### 15.5.2 Market data sources

Market data sources differ in coverage, latency, licensing, survivorship-bias controls, corporate-action handling, historical backfill quality, and commercial-use restrictions. Open or unofficial tools are useful for teaching, experimentation, and prototyping, but regulated production systems usually require licensed institutional feeds, service-level agreements, data-quality controls, and legal review.

SEC EDGAR is a filing-access system rather than a single curated NLP dataset [U.S. Securities and Exchange Commission, 2026]; tools such as yfinance are convenient for prototyping but should not be treated as institutional feeds without checking licensing, reliability, and data quality [Aroussi, 2026].

- **Yahoo Finance via yfinance:** Convenient access to historical OHLCV data for research and prototyping. It should not be treated as an institutional production feed without checking licensing, reliability, data quality, and Yahoo's terms of use.
- **Alpha Vantage:** Time-series and fundamental data through an API-key-based service.
- **Quandl/Nasdaq Data Link:** Macro, financial, and alternative datasets, with dataset-specific licensing.
- **IEX Cloud or similar providers:** Real-time and historical market data services subject to provider terms and exchange-data rules.
- **SEC EDGAR:** Public access to regulatory filings. It is a filing repository, not a ready-made NLP dataset, and requires parsing, cleaning, metadata extraction, and task-specific labeling before modeling.

| Resource | Typical size | Primary task | Description |
| :--- | :--- | :--- | :--- |
| Financial PhraseBank | 4,840 sentences | Sentiment analysis | Financial-news sentence sentiment dataset annotated by finance-aware annotators. Use an explicit agreement split, such as `sentences_75agree`, `sentences_66agree`, or `sentences_50agree`, because the number of usable examples depends on the selected annotator-agreement threshold. |
| FiQA | Version-dependent | Financial opinion mining and question answering | Benchmark family associated with financial opinion mining and QA. FiQA-SA sentiment variants are commonly reported with approximately 1,173 annotated financial headlines or posts, while QA and RAG reformulations use different splits and sizes. Always report the exact benchmark version and split. |
| FinEAS model/code | Model/resource | Financial sentiment embeddings and sentiment analysis | FinEAS provides a supervised sentence-embedding approach for financial sentiment. It is useful as a specialized encoder or scoring module, but its label mapping, training distribution, temporal coverage, and production suitability must be validated before institutional use. |
| SEC EDGAR | Millions of filings | Document retrieval, extraction, and filing analysis | SEC EDGAR is a public filing database rather than a single curated NLP dataset. LLM workflows usually require filing selection, parsing, cleaning, metadata extraction, section segmentation, and task-specific labeling before modeling. |
| Earnings calls | Varies by vendor or source | Transcription analysis, sentiment, forecasting, and event analysis | Quarterly earnings-call transcripts can support management-tone analysis, question-answer analysis, guidance extraction, and market-reaction studies. Coverage and licensing depend on the provider. |

The following examples show simple access patterns for retrieving market prices and SEC filings. They are intended for experimentation and should be adapted before use in production pipelines.

The first example downloads historical price data for a small list of tickers and returns a dictionary of data frames.

```python
import yfinance as yf
import pandas as pd

def get_market_data(tickers, period="1y", interval="1d"):
    """
    Download historical OHLCV data with error handling
    """
    data = {}
    for ticker in tickers:
        try:
            df = yf.download(ticker, period=period, interval=interval,
                             auto_adjust=True, progress=False)
            data[ticker] = df
        except Exception as e:
            print(f"Error fetching {ticker}: {e}")
            data[ticker] = pd.DataFrame()
    return data

# Example usage
if __name__ == "__main__":
    portfolio = ["AAPL", "MSFT", "JPM", "GS"]
    market_data = get_market_data(portfolio, period="5y")
```

The second example retrieves recent SEC filings for a ticker and shows a simplified text-extraction step.

```python
import sec_edgar_downloader
from pathlib import Path

class SECFilingRetriever:
    """
    Retrieve and process SEC filings
    """

    def __init__(self, company_name, email_address,
                 output_dir="./sec_filings"):
        self.output_dir = Path(output_dir)
        self.output_dir.mkdir(exist_ok=True)
        # sec_edgar_downloader requires an identity: SEC's fair-access policy
        # requires a declared company name and contact e-mail in the User-Agent.
        # Downloader(output_dir) alone does not match the current interface.
        self.downloader = sec_edgar_downloader.Downloader(
            company_name,          # e.g. "Example Research Ltd"
            email_address,         # e.g. "research@example.com"
            str(self.output_dir),
        )

    def get_filings(self, ticker, form_type="10-K", limit=5):
        """Download filings and return a typed record per filing.

        The previous version returned a DIRECTORY, which the caller then passed
        to extract_text(), which called open() on it -- IsADirectoryError. A
        filing is a package (primary document, exhibits, metadata), so the
        primary document must be selected explicitly, not assumed.
        """
        self.downloader.get(form_type, ticker, limit=limit)
        base = (self.output_dir / "sec-edgar-filings" / ticker / form_type)
        records = []
        for acc_dir in sorted(base.iterdir()):
            primary = acc_dir / "full-submission.txt"
            if not primary.exists():
                continue

            records.append({
                "ticker": ticker,
                "form": form_type,
                "accession": acc_dir.name,
                "primary_document": primary,
                # Availability time, NOT the period the filing covers.
                "available_at": datetime.fromtimestamp(
                    primary.stat().st_mtime).isoformat(),
            })

        return records

    def extract_text(self, record):
        """Extract text from a filing RECORD (not a directory)."""
        filing_path = record["primary_document"]
        # Production systems would use proper XBRL parsing
        with open(filing_path, 'r', encoding='utf-8', errors='ignore') as f:
            return f.read()

# Example usage
retriever = SECFilingsRetriever()
filing_dir = retriever.get_filings("AAPL", "10-K", limit=3)
```
