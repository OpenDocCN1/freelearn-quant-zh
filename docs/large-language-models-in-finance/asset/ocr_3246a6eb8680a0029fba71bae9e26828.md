# Product quantization

**Product quantization (PQ)** [Jégou et al., 2011] addresses a different challenge by focusing on memory efficiency rather than solely on search speed. It compresses embeddings by decomposing $d$-dimensional space into $s$ subspaces of dimension $d/s$:

$\mathbb{R}^d = \mathbb{R}^{d/s} \times \mathbb{R}^{d/s} \times \cdots \times \mathbb{R}^{d/s}$

Each subspace is then quantized independently using $k$ centroids. This allows the embedding to be represented in a compressed form requiring only $s \cdot \log_2(k)$ bits, compared to $32d$ bits for a standard float32.

While these indexing methods define how similarity search is performed, we rely on specialized libraries to implement them efficiently at scale.

# ## 4.5.2 Facebook AI Similarity Search (FAISS)

**Facebook AI Similarity Search (FAISS)** [Johnson et al., 2019, Douze et al., 2024] provides optimized implementations of a wide range of vector indexing and similarity search methods, making it a common choice for building production-grade retrieval systems. A typical workflow for constructing and querying an index is shown below:

```
import faiss
import numpy as np

# Index parameters
d = 768 # embedding dimension
nlist = 100 # number of clusters for IVF
m = 8 # number of subquantizers for PQ
nbits = 8 # bits per subquantizer

# Create IVF-PQ index
quantizer = faiss.IndexFlatL2(d)
index = faiss.IndexIVFPQ(quantizer, d, nlist, m, nbits)

# Train on sample embeddings
embeddings = np.random.randn(10000, d).astype('float32')
index.train(embeddings)
index.add(embeddings)

# Search
query = np.random.randn(1, d).astype('float32')
k = 5
distances, indices = index.search(query, k)
```
