# ## 3.8.2 Financial-specific validation

Standard NLP evaluation metrics, even when applied carefully, do not catch the failure modes that matter most in financial applications. A model can achieve high F1 on a held-out test set while still computing growth rates in the wrong direction, confusing quarterly and annual figures, or generating statements that cannot be verified against any source document. The three validation checks below address these failure modes directly and should be applied as a matter of course before any financial model is moved to production.

When evaluating **numerical accuracy**, financial outputs must be held to a higher standard of precision than general language generation. A model that rounds $1.401B to $1.4B may be acceptable in some contexts; one that reports revenue growth of +8% when the correct figure is –8% is not. The validation function below implements a relative-tolerance check that can be applied programmatically across a large test set, flagging outputs where the predicted value deviates from the ground truth by more than a specified threshold:

```
import math

def validate_calculation(prediction, ground_truth,
                         rel_tol=0.01, abs_tol=1e-8):
    """Check numerical agreement without dividing by zero."""
    if math.isclose(ground_truth, 0.0, abs_tol=abs_tol):
        return math.isclose(prediction, ground_truth, abs_tol=abs_tol)
    return math.isclose(
        prediction,
        ground_truth,
        rel_tol=rel_tol,
        abs_tol=abs_tol,
    )
```

The absolute-tolerance branch is essential when the ground truth is zero or economically close to zero, such as a spread change of 0 bps, a flat quarter-over-quarter growth rate, or a normalized exposure that should be exactly neutral. Manually dividing by `ground_truth` in these cases either fails numerically or turns small rounding noise into an artificially large relative error.

When assessing **temporal consistency**, the key concern is whether the model correctly handles directional comparisons across time periods. Many financial questions involve directional comparisons across time periods, and models frequently get the direction of subtraction wrong—computing _Q_<sub>1</sub> – _Q_<sub>2</sub> when asked for _Q_<sub>2</sub> – _Q_<sub>1</sub> growth. This is a systematic error that standard accuracy metrics may miss if the magnitudes happen to be similar.
