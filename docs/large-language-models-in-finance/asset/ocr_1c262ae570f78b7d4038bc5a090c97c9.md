# Graphics processing units (GPUs)

GPUs remain the most broadly supported accelerators for LLM training and serving because the CUDA ecosystem integrates mature compilers, kernels, communication libraries, profilers, and inference servers.

NVIDIA’s H100 SXM configuration provides 80 GB of HBM3 memory and approximately 3.35 TB/s of memory bandwidth [NVIDIA, 2026b]. Blackwell systems increase aggregate memory and bandwidth further: an eight-GPU DGX B200 is specified with 1.44 TB of total GPU memory and 64 TB/s of aggregate HBM3e bandwidth [NVIDIA, 2026a].

NVIDIA reported upper-bound speedups of up to nine times for training and up to thirty times for inference on selected large-language-model configurations relative to A100 systems [NVIDIA, 2022]. These figures are useful indicators of architectural potential, but they are vendor benchmarks rather than universal gains.

Realized performance depends on the model, precision, sequence lengths, batch size, concurrency, interconnect, software version, and latency constraint; a small financial classifier or a retrieval-heavy pipeline may obtain much smaller improvements.

GPU infrastructure offers three practical advantages for financial institutions. First, the software ecosystem supports both machine-learning workloads and conventional numerical computation. Second, the same cluster can be allocated across training, fine-tuning, embedding generation, and inference. Third, the broad cloud and original-equipment-manufacturer market provides multiple procurement routes.

The main disadvantages are power density, cooling requirements, specialized engineering effort, and vendor lock-in. An H100 SXM device can be configured up to roughly 700 W, while newer Blackwell devices can have still higher thermal design power; these figures exclude CPUs, memory, networking, storage, cooling overhead, and redundancy [NVIDIA, 2025]. Hourly GPU price is therefore not a sufficient cost measure.

# Tensor processing units (TPUs)

Google’s TPUs are application-specific integrated circuits designed for machine-learning matrix operations. A single TPU v5e chip provides 16 GB of high-bandwidth memory, 800 GiB/s of memory bandwidth, 197 TFLOPs of peak bfloat16 compute, and 393 TOPS of peak INT8 compute; the 393 figure is an integer-operation rate rather than bfloat16 floating-point performance [Google Cloud, 2026]. TPU v5e supports slices up to 256 chips, while larger TPU families target higher-scale training.
