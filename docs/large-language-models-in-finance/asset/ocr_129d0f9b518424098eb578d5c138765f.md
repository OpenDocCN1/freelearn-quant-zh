# 6.9 Implementation roadmap

A financial MCP deployment should progress in controlled stages rather than moving directly from a prototype to production use. Each stage should add capability only after the required controls, evidence, and operational ownership are in place. The roadmap below gives a practical sequence for introducing MCP-assisted workflows while limiting authorization, data, and execution risk.

+   1. **Inventory and classify.** Identify the proposed MCP servers, tools, data sources, side effects, system owners, users, and regulatory obligations. Each tool should be classified by business purpose, data sensitivity, permitted users, and whether it can create a financial or external side effect.

+   2. **Start read-only.** Begin with a small number of approved resources and deterministic calculations that do not change business state. At this stage, the system should retrieve, summarize, and calculate, but it should not create external communications, submit orders, modify records, or trigger operational actions.

+   3. **Build the control envelope.** Add identity propagation, policy-as-code, schema pinning, point-in-time checks, deterministic validation, and audit records before adding more intelligence or autonomy. The control envelope should be tested independently of the model.

+   4. **Add draft actions.** Permit the model to create proposals, tickets, memos, or reports that remain non-binding. These outputs should be clearly marked as drafts and routed through review workflows before they are used for client communication, regulatory reporting, trading, or risk decisions.

+   5. **Introduce approval-bound execution.** Allow execution only when the action is bound to a reviewed request through canonical hashes, idempotency keys, separation of duties, and reconciliation. Any material change to the request, evidence, policy version, or destination should invalidate the approval.

+   6. **Operate as a model-risk system.** Monitor drift, incidents, server changes, tool selection, refusals, escalation quality, latency, cost, and control failures. Model, prompt, schema, server, policy, and dependency changes should trigger risk-based revalidation before promotion.

This staged approach keeps MCP adoption aligned with financial model-risk management. The system earns additional capability only when the surrounding controls can demonstrate that the workflow remains authorized, auditable, recoverable, and safe to operate.
