# 15.6 Framework configurations, RAG, and evaluation utilities

This section provides practical configuration and utility examples that can support financial LLM development. The examples cover model configuration, retrieval-augmented generation (RAG), and evaluation metrics, but they should be adapted to the institution's infrastructure, data governance, and security requirements.

# 15.6.1 Example configuration for financial LLMs

The following YAML example shows how a financial LLM configuration might organize model, training, data, evaluation, deployment, and monitoring settings in one place.

Listing 15.3: Example configuration for a financial LLM workflow

```
# config/financial_llm_config.yaml
model:
  architecture: "transformer"
  hidden_size: 768
  num_layers: 12
  num_heads: 12
  dropout: 0.1
  layer_norm_eps: 1e-5
  max_position_embeddings: 512
  vocab_size: 30522
  financial_specializations:
    finbert_checkpoint: "ProsusAI/finbert"
    fineas_checkpoint: "LHF/FinEAS"
    fineas_use_case: "sentence-level financial sentiment and embedding geometry"

training:
  batch_size: 32
  learning_rate: 2e-5
  weight_decay: 0.01
  num_epochs: 3
  warmup_ratio: 0.1
  gradient_accumulation_steps: 1
  fp16: true

data:
  max_sequence_length: 512
  train_test_split: 0.9
  validation_split: 0.1
  preprocessing:
    lowercase: false # Preserve case for financial entities
    remove_html: true
    normalize_numbers: true

evaluation:
```
