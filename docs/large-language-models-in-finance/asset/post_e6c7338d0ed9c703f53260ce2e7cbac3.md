## 13.3.1 From language tokens to temporal tokens

The first technical obstacle is tokenization. Language models consume discrete tokens, while financial series are continuous, noisy, irregularly sampled, and often heavy-tailed. A daily return, an intraday quote update, a realized-volatility estimate, and an earnings-surprise variable do not resemble words in any literal sense. The modeling question is how to map a real-valued process into a representation that preserves economically relevant temporal structure without inventing spurious symbolic precision.

Let $r_t = \log(P_t/P_{t-1})$ denote a log return. A tokenizer is a map

$$\tau : (r_{t-L+1}, \dots, r_t) \mapsto (z_1, \dots, z_m),$$

where $z_i$ are tokens or embedded patches. Three families of tokenization are especially important.

- **Patching** divides a sequence into overlapping or non-overlapping windows. Given a patch length $P$ and stride $S$, the $j$-th patch is

$$X_j = (r_{jS+1}, \dots, r_{jS+P}).$$

The patch is then linearly projected into an embedding vector. This approach, used by PatchTST, is powerful because it reduces sequence length and makes long histories tractable [Nie et al., 2023]. Instead of attending over every daily return in several years of history, the model attends over patches that summarize local temporal motifs.

- **Quantization** maps normalized values to discrete bins. Chronos, for example, treats time-series forecasting as language modeling by scaling and discretizing values into a finite vocabulary [Ansari et al., 2024]. If $\tilde{r}_t$ is a normalized return, a quantizer maps it to

$$q_t = Q(\tilde{r}_t) \in \{1, \dots, B\},$$

where $B$ is the number of bins. The model then predicts future tokens autoregressively. This is elegant because it reuses language-model machinery, but it also introduces resolution limits: if tail events fall into coarse bins, the model may rank forecasts well while failing to estimate tail magnitudes accurately.

- **Learned codebooks** use vector quantization or representation learning to discover recurring temporal motifs. A learned tokenizer maps a segment $X_j$ to the nearest prototype in a codebook $\{e_1, \dots, e_K\}$:

$$z_j = \arg \min_k \|f(X_j) - e_k\|^2.$$

This concentrates representation capacity on recurring structures such as volatility bursts, liquidity shocks, trend reversals, or post-event drift. The cost is lower interpretability and the possibility of codebook drift when market regimes change.

For finance, tokenization must also respect scale. Raw prices are usually inappropriate because a price of 500 for one stock is not directly comparable to a price of 50 for another. Returns, standardized returns, realized-volatility-normalized returns, drawdowns, ranked transformations, or residuals after removing known factors are often more stable inputs. The transformation should be chosen according to the economic task: price-level forecasting, volatility forecasting, covariance estimation, regime detection, and event response all require different notions of invariance.

## 13.3.2 Architectures: Patch transformers, decoder-only TSFMs, and inverted attention

Modern TSFMs can be organized around how they define tokens and where attention operates. PatchTST treats temporal patches as tokens and applies a transformer encoder to long-horizon forecasting [Nie et al., 2023]. This is natural for financial series because local windows often encode short-lived patterns: volatility clustering, opening-auction effects, post-announcement drift, or intraday liquidity cycles.

Figure 13.2: Patch-based forecasting architecture.

A long numerical history is divided into contiguous temporal patches, and each patch — not each timestep — becomes one token. Attention then operates over P tokens rather than T, which both compresses the sequence and forces the model to attend to local segments that carry more signal than an individual observation does. The saving is quadratic, and it is what makes transformer machinery affordable on a long price history at all. Decoder-only TSFMs, such as TimesFM-style models, adapt the causal language modeling paradigm to forecasting [Das et al., 2024]. The model consumes a context window and generates future values or future distributional summaries. This architecture is attractive for zero-shot and few-shot forecasting because it resembles the generative structure of LLMs: a long history becomes a prompt, and the forecast horizon becomes the continuation.

Chronos and Chronos-2 represent the language-of-time approach more directly by tokenizing real-valued time series and learning a categorical likelihood over future tokens [Ansari et al., 2024, 2025]. This is a useful design when broad transfer matters. A model trained on many unrelated series can learn generic temporal features such as seasonality, trend changes, mean reversion, and burstiness. In finance, however, generic temporal skill must be separated from economically exploitable skill. A model can produce plausible forecasts for a return process without generating a tradable signal after costs.

The iTransformer changes the axis of attention. Instead of treating each time point as a token, it treats each variate as a token and applies attention across variables [Liu et al., 2024d]. For finance, this is especially important. A portfolio is not merely a collection of independent univariate series. Assets move through common risk factors, sector linkages, funding constraints, index membership, supply chains, and macro shocks. Cross-variate attention can therefore learn lead-lag effects, correlation clusters, and latent factor structures that a purely univariate model misses.

## 13.3.3 Cross-modality reprogramming and time-LLM

A distinct line of work asks whether a frozen language model can be reprogrammed for time-series forecasting. Time-LLM does this by converting numerical patches into embeddings that can be aligned with the latent space of an LLM, while also using natural-language prompts to describe the task and input context [Jin et al., 2024]. In finance, the appeal is immediate: the model may receive a prompt such as “forecast the next 20 business days of returns for a large-cap technology stock using the last 512 observations,” plus summary statistics such as recent volatility, trend, drawdown, and calendar context.

Numerical patches are projected into a representation the backbone can consume, allowing a language model’s pretrained infrastructure to be reused for temporal prediction without fine-tuning its weights. The architecture is elegant and the engineering is real. Neither fact is evidence that the resulting forecast has economic value, and the amber panel is in this figure rather than in a footnote because that is the confusion the approach most often invites. This design is conceptually powerful because it separates three objects: the raw time series, the learned bridge that maps time-series patches into language-model space, and the textual prompt that conditions the task. The prompt can encode horizon, asset class, sampling frequency, macro environment, or whether the target is return, volatility, covariance, or drawdown. But the method also raises a practical question: does the language model’s pretrained semantic knowledge truly improve the numerical forecast, or does the system work mainly because the reprogramming layer learns a useful temporal representation? In financial applications, this distinction matters because the former suggests reusable financial reasoning, while the latter suggests a sophisticated but ordinary sequence model.
