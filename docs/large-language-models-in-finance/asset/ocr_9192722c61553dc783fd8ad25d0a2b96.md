and the two coincide only when the factors are exactly mean-zero in sample — which they are not. Had the objective above omitted \(\alpha\), its solution would have been \(\mathbb{E}[FF^{\top}]^{-1}\mathbb{E}[FRe]\), the uncentered projection, and the covariance formula would not apply. The two coincide only for mean-zero factors. This is the error the definition is written to foreclose, and it is worth stating plainly because it is the most common way reported “alpha” turns out to be the mean of a residual rather than an intercept. The adjective “generative” describes the provenance of the candidate strategy or contract; it does not create a new exemption from conventional asset-pricing and statistical tests. In finite samples, \(\hat{\alpha}_g\) must be reported together with the estimation window, factor universe, transaction-cost model, multiple-testing adjustment, and out-of-sample protocol.

This definition deliberately separates economic novelty from empirical validation. A model may generate an original-looking rule whose estimated \(\alpha_g\) is entirely due to data snooping, omitted risks, market impact, or an unrealistic simulation. The term is useful only when accompanied by a documented search process and a credible evaluation protocol.

# 14.3.2 Sources of Generative Alpha

Four broad mechanisms organize the discussion. First, an agent can generate and test trading or allocation rules. Second, it can design customized contracts whose payoffs match a client’s constraints. Third, it can adapt market-making and execution policies to changing liquidity. Fourth, it can help create new contract or market structures. Figure 14.2 summarizes these four pillars before the subsections examine them individually.

# Automated strategy generation

Instead of relying exclusively on manually specified strategies, an agent can search a structured space of signals, transformations, portfolio rules, and risk constraints. Evolutionary search is one possible mechanism:

```
Algorithm 20 Governed evolutionary strategy search
Define a temporally valid training window, validation window, and untouched test window

Initialize a population \(P_0\) of \(N\) admissible strategy specifications
for each generation \(g = 1\) to \(G\) do
    Evaluate each strategy using costs, turnover, risk limits, and validation data only
    Penalize complexity, instability, and similarity to previously tested strategies
    Select parents from \(P_{g-1}\) using validation fitness
    Generate candidates through constrained crossover and mutation
    Reject candidates that violate data-timing, leverage, or implementation rules
    Preserve an audit log of all trials, not only the surviving strategy
end for
Freeze the selected specification before evaluating the untouched test period
return Selected strategy, trial ledger, and out-of-sample report
```
