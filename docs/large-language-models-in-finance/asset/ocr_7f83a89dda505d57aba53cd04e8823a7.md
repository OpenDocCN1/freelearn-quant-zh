# 4.7.1 Query expansion

The goal of query expansion is to compensate for the fact that user queries are often short, underspecified, or phrased very differently from the relevant documents. Instead of matching the literal query against the index, we transform it into one or more richer surrogate queries that are more likely to retrieve the right passages.

# Hypothetical Document Embeddings (HyDE)

HyDE [Gao et al., 2023a] addresses the query–document mismatch by asking the language model to draft a plausible answer and then using that draft as the actual query. Because the hypothetical answer is written in the same register as the documents in the corpus, its embedding tends to land much closer to the relevant passages than the embedding of the original short user query.

```
Algorithm 10 HyDE retrieval
1: Input: Query q, LLM M, embedding function f, vector DB V
2: Generate hypothetical document: d_h <- M("Write answer to: q")
3: Embed hypothetical document: e_h <- f(d_h)
4: Retrieve: {d_1, ..., d_k} <- V.search(e_h, k)
5: return {d_1, ..., d_k}
```

# Multi-query retrieval

Where HyDE generates one synthetic answer, multi-query retrieval generates several reformulations of the original query and unions their results. The objective here is improved recall: even if the user phrasing fails to match a relevant passage, one of the variants is likely to. The cost is additional retrieval calls and a deduplication step at the end.

```
Algorithm 11 Multi-query retrieval
1: Input: Query q, LLM M, variants n_v
2: Generate variants: {q_1, ..., q_nv} <- M("Generate variants of: q")
3: Initialize results: R <- empty set
4: for each q_i in variants do
5:   R_i <- V.search(f(q_i), k)
6:   R <- R U R_i
7: end for
8: Deduplicate and rank by frequency
9: return top-k from R
```
