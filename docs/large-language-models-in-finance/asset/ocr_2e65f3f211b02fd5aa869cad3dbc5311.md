In trading applications, this formalism is useful even when the agents are not truly strategic in the game-theoretic sense: it forces us to specify what each role observes, what it is allowed to recommend, and how conflicts are resolved. Formally, we can view a debate-based trading system as a Markov game with:

+   - a global state \( s_t \) containing market variables, news, current positions, and risk limits;
+   - per-agent observations \( o_t^k = g_k(s_t) \), where each observation map \( g_k \) selects the information relevant to role \( k \);
+   - per-agent policies \( \pi_{\theta_k}(a_t^k \mid o_t^k) \) for \( k = 1, \dots, K \), producing role-specific proposals or critiques; and
+   - a coordination mechanism that aggregates agent outputs into a final trading action \( a_t \) or into an escalation decision for human review.

A stylized aggregation rule is as follows:

\( a_t^* = \arg \max_{a \in \mathcal{A}} \sum_{k=1}^K w_k q_k(a; s_t) \),

where \( q_k(a; s_t) \) is a score produced by agent \( k \) for action \( a \) given state \( s_t \), and \( w_k \) reflects the agent's authority or role weight (e.g. risk manager vs trader).

**Implementation sketch.** The following repository-style skeleton shows how the aggregation rule in Equation (12.11) can be implemented without treating the code block as a numbered object. It aggregates multiple LLM-based agent proposals into a single trading action and performs a simple policy-gradient style update:

def aggregate_actions(agent_outputs, role_weights):
    # agent_outputs: list of dicts with {'action': a, 'score': q, 'role': r}
    aggregated_scores = defaultdict(float)
    for out in agent_outputs:
        a = out["action"]
        q = out["score"]
        w = role_weights[out["role"]]
        aggregated_scores[a] += w * q
    # pick action with highest weighted score
    return max(aggregated_scores.items(), key=lambda x: x[1])[0]
