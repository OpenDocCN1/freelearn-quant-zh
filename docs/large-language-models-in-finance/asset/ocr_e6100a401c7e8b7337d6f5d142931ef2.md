# 3.5.6 Choosing between full fine-tuning, LoRA, and QLoRA

From a practitioner’s perspective, the main question is not which method is “best” in the abstract, but which method is appropriate under given constraints (data, compute, governance). The choice typically reduces to a few practical considerations: how much GPU memory is available, how many distinct tasks must be served from a single base model, and how stringent the latency and governance requirements are. Table 3.4 summarizes the trade-offs for typical institutional scenarios. The general recommendation that emerges is to use full fine-tuning only when very large curated datasets exist and maximum task accuracy is essential (for instance, a core credit-scoring model); to use LoRA as the default for most adapter-style tasks; and to reserve QLoRA for settings where 13B or larger models must run on a single GPU.

| Aspect | Full fine-tuning | LoRA | QLoRA | Best use cases |
| :--- | :--- | :--- | :--- | :--- |
| GPU memory | Very high (all params + optimizer) | Moderate (few %) | Low (4-bit base + adapters) | QLoRA for 13B+ models in banks |
| Data requirements | Higher (more capacity to fit) | Moderate | Moderate | Full FT for very large curated datasets |
| Inference changes | New checkpoint per task | Shares base, swaps adapters | Shares 4-bit base, swaps adapters | LoRA/QLoRA for many narrow tasks |
| Stability / risk | More risk of catastrophic forgetting | Safer if base frozen | Safer, but quantization artifacts | Full FT for domain pre-training; PEFT for tasks |
| Operational aspects | Heavy deployment rollback | Lightweight: adapter routing | Lightweight: quantization infra needed | PEFT for fast experimentation and A/B tests |

Table 3.4. Qualitative comparison between full fine-tuning, LoRA, and QLoRA for financial applications

Method choice also depends on deployment scale. Table 3.5 makes the planning assumptions explicit, including the compute-cost row that is often missing from purely algorithmic comparisons. The estimates are order-of-magnitude planning guides, not vendor quotes; actual cost depends on cloud provider, utilization, security requirements, context length, and whether the workload is training, batch inference, or interactive inference.
