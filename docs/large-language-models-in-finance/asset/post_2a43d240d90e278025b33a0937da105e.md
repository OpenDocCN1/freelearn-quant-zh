
## Applications of LLMs in Finance

This chapter explores concrete applications of Large Language Models (LLMs) across the front, middle, and back offices of financial institutions. Here, front office refers to revenue-generating functions such as trading, middle office covers risk and control functions, and back office covers operations and processing. Rather than treating models as isolated components, we view them as building blocks inside complete decision pipelines (full path from data intake to model processing, human review, action, and monitoring) for trading, risk management, banking operations, fraud detection, and regulatory compliance [Cao, 2022, Yang et al., 2020].

The focus is deliberately architectural. For each use case we describe:

- the **inputs** (data sources and their structure),
- the **processing pipeline** (models, RAG indices, agents, tools),
- the **outputs** (signals, scores, reports, alerts),
- and the **control layer** (limits, approvals, logs, monitoring).

We avoid performance claims or invented metrics; any real deployment must be validated on proprietary data under a rigorous model-risk framework [Danielsson et al., 2016].

Throughout this chapter, we reuse the *Financial LLM Stack* introduced earlier. This stack refers to the layers needed to build, connect, deploy, and govern LLM-based financial systems. In the stack below, *tool-context integration* is used as the generic architectural term: it includes Model Context Protocol (MCP)-style interfaces when an institution adopts MCP, but it also includes proprietary API gateways, internal service buses, workflow engines, and direct integrations with risk, order-management, compliance, and document systems.

*Data → Pretraining → Fine-tuning → RAG → Agents → Tool-context integration → RL / Alignment → Infrastructure → Governance → Frontier.*

Each section illustrates how different parts of this stack come together in production-grade workflows. We begin with the front office, where LLM applications are closest to investment decisions, market interpretation, and trading workflows.

## 7.1 Front office: Market analysis and trading

Front-office activities include market analysis, signal generation, discretionary and systematic trading, and portfolio construction. These applications are especially sensitive because errors can directly affect trading decisions, portfolio risk, and client outcomes. LLMs can supplement traditional quantitative methods by making unstructured information, such as filings, news, research, transcripts, and even trader chat, machine-usable at scale [Wu et al., 2023b, Lopez-Lira and Tang, 2023].

### 7.1.1 Hybrid time-series and text forecasting

Classical time-series models (ARIMA, GARCH, state-space models, LSTMs, Transformers) operate on numerical inputs such as prices, volumes, and macroeconomic indicators [Tsay, 2010, Bollerslev, 1986, Hochreiter and Schmidhuber, 1997, Vaswani et al., 2017]. For example, an earnings warning or central-bank speech can quickly affect asset prices. However, in practice, price formation is strongly influenced by textual information, such as:

- earnings releases and conference calls [Tetlock, 2007, Jegadeesh and Wu, 2013],
- macro data releases and central-bank speeches [Hansen et al., 2018, Ehrmann and Wabitsch, 2022],
- rating-agency announcements [Cornaggia et al., 2018],
- major news and corporate actions [Tetlock, 2007, Calomiris and Mamaysky, 2019].

LLMs allow us to convert such text into numerical representations that can be integrated into forecasting models. The resulting *hybrid* architecture combines:

- 1. a **text-processing layer** that encodes documents into embeddings or structured signals;
- 2. a **feature layer** that aggregates text-derived signals with traditional quantitative features; and
- 3. a **forecasting model** that consumes the joint feature space.

### Architecture

Let $r_{t+1}$ denote the log-return between $t$ and $t + 1$, $\mathbf{x}_t$ the numerical features at time $t$ (returns, volatility, macro indicators), and $\mathbf{z}_t$ the text-derived features summarizing all documents observed in $(t - 1, t]$ that are relevant to the instrument or index under study. In simple terms, the model combines market data and document-derived signals to forecast the next-period return. A hybrid forecaster can be written as

$$\widehat{r}_{t+1} = f_\theta(\mathbf{x}_t, \mathbf{z}_t),$$ (7.1)

Here, the target is the next return, while the inputs combine numerical market features and text-derived features. The function $f_\theta$ is learnt on historical data [Gu et al., 2020, Chen et al., 2024a].

The text pipeline typically proceeds as:

- 1. collect raw documents (news, filings, transcripts),
- 2. clean, deduplicate, and map records to point-in-time issuer and security identifiers,
- 3. encode each document into a vector or structured summary [Reimers and Gurevych, 2019, Gao et al., 2021],
- 4. aggregate per instrument and time bucket, such as a day, hour, or event window, into z_t.

Aggregation may be as simple as averaging embeddings or as sophisticated as attention-based pooling weighted by recency or source reliability [Yang et al., 2016, Lin et al., 2017].

### A simple hybrid pipeline for daily forecasting

The following listing shows a minimal example of a daily hybrid pipeline for an equity index. The example uses public-style data sources only to show the structure of the workflow. It is an illustrative template, not production code. In a live trading context, this type of pipeline would require backtesting, risk analysis, validation, and monitoring before use.

### Listing 7.1: Minimal hybrid forecasting pipeline with prices and news

```
# Illustrative template. Not production code.
# Evaluation, risk limits, and validation omitted for brevity.

import pandas as pd
import numpy as np
import yfinance as yf
from transformers import AutoTokenizer, AutoModel
from sklearn.ensemble import RandomForestRegressor
import torch

# 1. Download price data
ticker = "SPY"
data = yf.download(ticker, period="10y", interval="1d")

# Robust choice of price column (Adj Close if available, else Close)
price_col = "Adj Close" if "Adj Close" in data.columns else "Close"
data["ret_1d"] = data[price_col].pct_change()
data["target"] = data["ret_1d"].shift(-1)

# 2. Load daily news headlines (pre-collected)
# Assumed format: columns: date (YYYY-MM-DD), headline (str)
news_df = pd.read_csv("daily_news.csv", parse_dates=["date"])

# 3. Aggregate news by day
daily_headlines = (
    news_df
    .groupby("date")["headline"]
    .apply(lambda x: " ".join(x))
    .sort_index()
)
```

### 4. Load text encoder (sentence embeddings)

```
model_name = "sentence-transformers/all-MiniLM-L6-v2"
tokenizer = AutoTokenizer.from_pretrained(model_name)
encoder = AutoModel.from_pretrained(model_name)

def embed_text(texts, batch_size=16):
    all_vecs = []
    for i in range(0, len(texts), batch_size):
        batch = texts[i:i + batch_size]
        inputs = tokenizer(
            batch,
            padding=True,
            truncation=True,
            return_tensors="pt"
        )
        with torch.no_grad():
            out = encoder(**inputs).last_hidden_state[:, 0, :]
        all_vecs.append(out.cpu().numpy())
    return np.vstack(all_vecs)
```

```
news_embeddings = embed_text(daily_headlines.tolist())
news_features = pd.DataFrame(
```
