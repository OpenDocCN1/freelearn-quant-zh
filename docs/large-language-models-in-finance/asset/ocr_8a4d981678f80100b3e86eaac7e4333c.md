Figure 12.2: Schematic role separation in a graph-based fraud architecture.

The supervised graph model produces the primary alert or risk score, while the LLM layer supports feature enrichment, explanation, and analyst triage.

Let $G = (V, E)$ denote a transaction graph with node features $x_v$ and edge features $e_{uv}$. A generic graph transformer updates node representations via

$h_v^{(l+1)} = \text{GT}\left(h_v^{(l)}, \{h_u^{(l)}, e_{uv}\}_{u \in \mathcal{N}(v)}\right),$ (12.19)

where GT is a multi-head attention mechanism over neighbours:

$\alpha_{uv} = \text{softmax}_u\left( \frac{(W_Q h_v^{(l)})^\top (W_K h_u^{(l)} + W_E e_{uv})}{\sqrt{d_k}} \right),$ (12.20)

\(\tilde{h}_v^{(l+1)} = \sum_{u \in \mathcal{N}(v)} \alpha_{uv} W_V h_u^{(l)},$ (12.21)

\(h'_v = \text{LN}(h_v^{(l)} + \tilde{h}_v^{(l+1)}),$ (12.22)

\(h_v^{(l+1)} = \text{LN}(h'_v + \text{FFN}(h'_v)),$ (12.23)

with $W_Q, W_K, W_V, W_E$ learnable matrices.

LLMs can extend this architecture, but in three distinct roles:

+   * **Feature extraction.** An LLM can convert unstructured material such as e-mails, KYC documents, support tickets, analyst notes, or case narratives into structured attributes that enrich $x_v$ or $e_{uv}$.
+   * **Rationale generation.** After a supervised detector has produced an alert, an LLM can draft a natural-language explanation that cites the graph paths, transaction bursts, entities, and documents supporting the flag.
+   * **Analyst tooling.** An LLM interface can allow investigators to ask questions about a case, retrieve linked evidence, compare similar historical alerts, or prepare an escalation memo.
