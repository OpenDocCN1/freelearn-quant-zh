Tool-access leakage is even more subtle. An agent equipped with retrieval, web search, market-data APIs, vector databases, or code execution may access current information while being evaluated on a historical date. A valid historical backtest must time-travel all tools. The retrieval index must contain only documents available at the forecast origin. Market-data APIs must be queried through point-in-time snapshots. Web search should be disabled unless a historical search index is available. Code tools should not load files produced after the origin.

# 13.4.8 Memory contamination in agentic backtests

Agentic systems add state. An agent may remember previous conversations, previous forecasts, previous errors, analyst feedback, tool outputs, or evaluation outcomes. This is useful in production but dangerous in backtesting. If the agent evaluates many historical dates sequentially and retains memory, it can learn from future test outcomes as the backtest progresses. The contamination is especially severe when the backtest order is chronological but the agent receives labels after each step; by the end, it has effectively been trained on the test set.

A valid agentic backtest must define a memory policy. For pure out-of-sample evaluation, memory should be reset at each forecast origin or restricted to information that would have been accumulated in a real live deployment up to that date. If the evaluation allows online learning, then the protocol must state exactly when labels become available and how updates occur. There is nothing wrong with online learning, but it must be simulated with realistic delays and without access to future labels.
