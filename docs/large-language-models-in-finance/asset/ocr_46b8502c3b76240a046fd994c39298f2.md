# To get the most out of this book

This book combines conceptual explanation, mathematical notation, code examples, and governance discussion. The mathematics is included to clarify assumptions, guarantees, and limitations. The code is included to show where those assumptions enter implementation and what must be checked, logged, or escalated before a financial workflow can be trusted.

The book follows a deliberate pattern: every substantial technical construction is motivated by a financial problem, formalized by explicit mathematical objects, translated into inspectable code or pseudocode, and then bounded by governance controls. Readers should therefore read formulas, algorithms, and examples together. The formula identifies the contract, the code implements the contract, and the governance layer records whether the contract was respected in production.
