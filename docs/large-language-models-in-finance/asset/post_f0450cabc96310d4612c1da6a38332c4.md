
## 4.8.1 System architecture

The class below wires up an embedding function, a vector collection, a retrieval method, and a generation method that together implement the online half of the pipeline. The constructor configures the vector store and the embedding model; `add_documents` handles indexing; `retrieve` performs similarity search with optional metadata filtering; `generate_response` formats the retrieved passages into a grounded prompt and calls the LLM with a system message that requests citation behavior; and `query` composes these into the end-to-end RAG call that user-facing code is expected to invoke. Prompt instructions are useful guardrails, but they are not compliance controls by themselves; production systems still need deterministic permission checks, output validation, and human escalation paths.

## Listing 4.1: Financial RAG system implementation

```
import os
from typing import List, Dict, Optional

from openai import OpenAI
import chromadb
from chromadb.utils import embedding_functions

class FinancialRAGSystem:
    """Pedagogical RAG system for financial document Q&A."""

    def __init__(self,
                 openai_api_key: str,
                 collection_name: str = "financial_docs",
                 embedding_model: str = "text-embedding-3-large"):
        self.client = OpenAI(api_key=openai_api_key)
        self.embedding_model = embedding_model

        # Initialize ChromaDB
        self.chroma_client = chromadb.Client()
        self.embedding_fn = embedding_functions.OpenAIEmbeddingFunction(
            api_key=openai_api_key,
            model_name=embedding_model
        )

        self.collection = self.chroma_client.get_or_create_collection(
            name=collection_name,
            embedding_function=self.embedding_fn
        )

    def add_documents(self,
                      documents: List[str],
                      metadatas: Optional[List[Dict]] = None,
                      ids: Optional[List[str]] = None):
        """Add documents to the vector store."""
        if ids is None:
            ids = [f"doc_{i}" for i in range(len(documents))]

        self.collection.add(
            documents=documents,
            metadatas=metadatas,
            ids=ids
        )

    def retrieve(self, query: str, n_results: int = 5,
                 where: Optional[Dict] = None) -> List[Dict]:
        """Retrieve relevant documents."""
        results = self.collection.query(
            query_texts=[query],
            n_results=n_results,
            where=where
        )

        return [{
            'document': doc,
            'metadata': meta,
            'distance': dist
        } for doc, meta, dist in zip(
            results['documents'][0],
            results['metadatas'][0],
            results['distances'][0]
        ])

    def generate_response(self,
                          query: str,
                          retrieved_docs: List[Dict],
                          model: Optional[str] = None) -> str:
        """Generate response using retrieved context."""
        # Format context
        context = "\n\n".join([
            f"Document {i+1} (Source: {doc['metadata'].get('source', 'Unknown')}):\n"
            f"{doc['document']}"
            for i, doc in enumerate(retrieved_docs)
        ])

        # Create prompt
        system_instructions = """You are a financial research assistant.

Rules:
1. Only use information from the provided documents
2. Cite sources using document numbers
3. If information is not in documents, say so
4. Be precise with financial figures
5. Highlight any uncertainties or conflicts
6. Do not give personalized investment advice
7. Escalate suitability, tax, legal, or compliance questions
to a qualified human reviewer"""
        user_input = (
            f"Context: \n{context}\n\n"
            f"Question: {query}\n\n"
            "Provide a detailed answer with citations."
        )

        # Configure the exact supported model and record it in the audit log.
        model = model or os.environ.get("OPENAI_MODEL")
        if not model:
            raise ValueError("Set OPENAI_MODEL or pass an explicit model ID")

        response = self.client.responses.create(
            model=model,
            instructions=system_instructions,
            input=user_input,
        )

        return response.output_text

    def query(self,
              question: str,
              n_results: int = 5,
              where: Optional[Dict] = None,
              model: Optional[str] = None) -> Dict:
        """End-to-end RAG query."""
        # Retrieve
        retrieved_docs = self.retrieve(question, n_results, where)

        # Generate
        answer = self.generate_response(question, retrieved_docs, model)

        return {
            'question': question,
            'answer': answer,
            'sources': retrieved_docs
        }
```

## 4.8.2 Document processing pipeline

The system above assumes that documents are already clean strings ready to be indexed. In practice, this is rarely the case for financial corpora: filings arrive as PDFs with multi-column layouts and embedded tables, transcripts contain speaker tags and timestamps, and internal documents drag along headers, footers, and page numbers that pollute embeddings. The DocumentProcessor class below addresses this by separating ingestion into three composable stages—extract, clean, chunk—each of which can be adapted independently for a given document type. We walk through the three stages in turn after the listing.

## Listing 4.2: Financial document processing

```
from typing import Dict, Optional

import PyPDF2
import re

class DocumentProcessor:
    """Process financial documents for RAG ingestion."""

    @staticmethod
    def extract_text_from_pdf(pdf_path: str) -> str:
        """Extract text from PDF."""
        with open(pdf_path, 'rb') as file:
            pdf_reader = PyPDF2.PdfReader(file)
            text = ""
            for page in pdf_reader.pages:
                text += page.extract_text()

        return text

    @staticmethod
    def clean_financial_text(text: str) -> str:
        """Clean and normalize financial document text."""
        # Remove excessive whitespace
        text = re.sub(r'\s+', ' ', text)

        # Normalize currency symbols
        text = text.replace('$', ' USD ')

        # Remove page numbers and headers
        text = re.sub(r'Page \d+', '', text)

        return text.strip()

    @staticmethod
    def chunk_with_metadata(text: str,
                            chunk_size: int = 1000,
                            overlap: int = 200,
                            document_metadata: Optional[Dict] = None):
        """Chunk text and attach metadata."""
        chunks = []
        tokens = text.split()

        for i in range(0, len(tokens), chunk_size - overlap):
            chunk_text = ' '.join(tokens[i:i + chunk_size])

            chunk_metadata = {
                'chunk_id': i // (chunk_size - overlap),
                'start_pos': i,
                'end_pos': min(i + chunk_size, len(tokens))
            }

            if document_metadata:
                chunk_metadata.update(document_metadata)

            chunks.append({
                'text': chunk_text,
                'metadata': chunk_metadata
            })

        return chunks
```

The first stage, `extract_text_from_pdf`, lifts raw text out of a PDF using PyPDF2. This is intentionally minimal: production deployments typically replace it with a layout-aware extractor (e.g. `pdfplumber`, `unstructured`, or a vision-language model) that preserves tables and reading order, both of which matter substantially for filings such as 10-Ks.

The second stage, `clean_financial_text`, applies normalization that protects retrieval quality downstream. Collapsing whitespace prevents tokenizers from being misled by line breaks introduced during PDF extraction; rewriting $ as USD avoids tokenization quirks around currency symbols and makes amounts more searchable; and stripping recurring page-number boilerplate prevents these strings from dominating BM25 scores in hybrid retrieval. As with extraction, this is a reasonable starting point that should be extended with domain-specific rules—ticker normalization, footnote handling, table-to-text conversion—for any serious deployment.

The third stage, `chunk_with_metadata`, performs fixed-size chunking with overlap and, crucially, attaches metadata to every chunk. Document-level metadata such as company, filing type, section, or filing date is propagated into each chunk so that the metadata filtering described in the previous section becomes possible at query time. This is the bridge that connects offline ingestion to online retrieval: without good metadata at this stage, no amount of clever ranking later can recover information about *which* document a passage came from.

## 4.9 Advanced RAG patterns

The baseline RAG pipeline retrieves once, generates once, and returns. This is sufficient for many financial Q&A tasks, but it has well-understood failure modes: it cannot recognize that retrieval has gone wrong; it cannot decide that retrieval is unnecessary; and it cannot mix retrieval with other forms of reasoning, such as numerical computation or web search. The patterns covered in this section are targeted remedies for these failure modes. **Corrective RAG** adds a quality gate that detects bad retrieval and recovers from it; **Self-RAG** promotes retrieval and self-critique to first-class decisions made by the model itself; and **Agentic RAG** embeds retrieval inside a broader tool-using reasoning loop.
