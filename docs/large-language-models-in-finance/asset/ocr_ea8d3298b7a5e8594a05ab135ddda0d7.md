```
Algorithm 14 Agentic RAG loop
1: Input: Query q, tools T = {retrieve, calculate, search_web, finish}
2: Initialize conversation C ← [q]
3: for step = 1 to max_steps do
4:   Generate thought: thought ← LLM(C)
5:   Parse action: (action, params) ← Parse(thought)
6:   if action = finish then
7:     return params["answer"]
8:   end if
9:   Execute: observation ← T[action](params)
10: C ← C ∪ [thought, observation]
11: end for
12: return error (max steps exceeded)
```

This approach allows the system to:

+   • Decide when retrieval is needed
+   • Combine multiple tools (retrieval, calculation, web search)
+   • Reason about intermediate results
+   • Iteratively refine answers

# 4.9.4 Choosing between advanced RAG patterns

The advanced patterns introduced in this section can be interpreted as targeted remedies for characteristic failure modes of basic RAG systems. Table 4.3 summarizes their core ideas, principal financial use cases, and the main trade-offs involved.

| Pattern | Core idea | When to use | Trade-offs |
|---|---|---|---|
| Corrective RAG (CRAG) | Assess and repair retrieval quality | Noisy corpora, mixed-quality disclosures, heterogeneous sources | Extra latency; requires reliable meta-evaluation. |
| Self-RAG | Let the model decide when and what to retrieve | Complex questions where information may or may not be in the corpus | More complex prompting and control flow. |
| Agentic / tool-augmented RAG | Combine retrieval with tools and multi-step reasoning | Scenario analysis, stress testing, and complex regulatory questions | Highest implementation complexity; requires orchestration and governance. |
