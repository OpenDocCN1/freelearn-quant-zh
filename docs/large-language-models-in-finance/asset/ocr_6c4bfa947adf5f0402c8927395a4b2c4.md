**Definition 13.5.1** (Prefix-causal artifact). Let $H$ be a complete history of source records, each carrying an availability stamp, and let $B_t(H, \xi_t)$ be a build map that is formally allowed to receive the complete history. The build map is *prefix causal* at cutoff $q_t$ when there exists a measurable map $\widetilde{B}_t$ with $B_t(H, \xi_t) = \widetilde{B}_t(H_{\le q_t}, \xi_t)$ for every complete history $H$: two histories that agree through $q_t$ produce the same artifact under the same ex-ante random state. An artifact is point-in-time admissible for decision date $d$ only if its build factors through the historical prefix in this sense and $\rho(\mathcal{A}_t) \le q_d$.

Two conditions make this operative rather than decorative. The random state $\xi_t$ must be drawn *ex ante* and fixed — shared across the two histories in the definition — since a build that reseeds on the data it sees is not a function of the prefix alone. And every third-party component (a hosted model behind an API, a managed embedding endpoint, a vendor retrieval index) must be pinned to an immutable version identifier. A mutable API alias silently violates prefix causality without changing a single line of the caller's code, and it is the one violation that survives every code review, because the code did not change.

The clock matters as much as the artifact. Each trading day $d$ on a venue-specific calendar has a decision cutoff $q_d$ before intended execution, such as the market-on-close deadline. An article with first vendor availability $u_j$ and end-to-end latency $\lambda_j$ (ingestion, parsing, inference, routing) has effective trading date

```
$d(j) = \min\{d \in \mathcal{T} : u_j + \lambda_j \le q_d\},$ (13.4)
```

where $\mathcal{T}$ is the venue's trading calendar — an explicit, versioned list of sessions with their cutoffs, including early closes and holidays, and not a generic business-day rule. Late news rolls forward to the next admissible session in $\mathcal{T}$ and is never assigned backward. If no session in the evaluation window satisfies the constraint (the article arrives after the last cutoff), the score is *undefined* rather than deferred to a session outside the sample; silently deferring is how coverage leaks back into a supposedly clean run. The deployed vintage is the latest admissible artifact by that cutoff, $v(j) = \max\{t : \rho(\mathcal{A}_t) \le qd(j)\}$, with no backfilling: if no admissible artifact exists, the score is missing rather than imputed. Forward labels follow the same discipline. An $h$-session label for article $j$ completes at $k_j = \sigma^h(d(j))$, where $\sigma$ is the successor map on the trading calendar $\mathcal{T}$ — *not* integer addition on dates, which would silently cross weekends and holidays and shorten the true realization lag. A model built at vintage $t$ may train only on labels with $k_j < t$; conditioning instead on $d(j) < t$ silently admits the $h$ most recent cohorts before their outcomes are known, a label-realization leak that survives many code reviews.
